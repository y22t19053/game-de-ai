# 交付闸门

## 什么时候用

- 想报「完成 / 上线 / 可用」。
- 月末或季度复盘，决定一个项目去留。
- 一个事聊了很久还在改方案（刀柔会六个月只出手册、零实战）。

## 只问四个问题

1. 有链接吗？（线上地址、商店页、repo、成片）
2. 有外部的人用过吗？几个？他们说了什么？
3. 如果没人用：是没发出去，还是发出去了没人要？
4. 下一步「发出去的最小动作」是什么？——≤30 分钟能做完的那一步。

## 判据

- 1043 次提交、0 个外部玩家 = 没交付。
- 三天做出一个能打开的链接 = 交付了。
- 稿子写完没发、海报做完没投、名字想好没注册 = 在攒素材，不是在交付。
- 六结局矩阵只有 2/6 被真人走过，就不算「做完了」。

## 把计划压成一次能跑的事

停摆的项目只写两行：**最小动作 + 花费**。

- 规模：3–5 人、90 分钟、0 场地、2 个模块；拒绝加模块。
- 首跑之前不改版本（手册、规则、美术都不动）。
- 卡在具体零件上的，写清零件与价钱：训练刀差一颗 PIC12F629（≈100 元）就能「能响能亮」——这就是最小动作，不是「继续打磨」。

## 收口动作

- 每条反馈落成 issue：复现步骤 + 期望 + 断言（怎么算修好）。
- 「历来反馈一个都没修」的债，当天清一条，不攒成复利。
- 复盘表只留三列：项目 | 外部证据 | 处置（继续 / 降级 / 归档 / 退役）。

## 反例

- 名言库 2000 条：连打约 20 次「继续」仍未完成——攒素材式拖延。
- 摆摊 / 线下活动办过一次没人来，却继续改规则。
- 用购买替代训练：器材纠结一个月，实战一次没打。
