# 需求 → 任务书

## 什么时候用

- 用户只发「继续」「优化一下」「做个海报」这类一句话需求。
- 要把任务交给别的 agent 或另一个模型。
- 发现自己正准备「猜需求」然后动手。

## 先反问（三个，一次问完）

1. **交付物是什么形态？** 可打开的文件 / 线上链接 / 一段文字 / 一张图。
2. **明确不要什么？** 禁止项比要求更省时间。
3. **怎么算完成？** 谁看、看什么、什么算过。

用户答「都行」时，给两个具体选项让他挑，不要自己定。

## 再写任务书（9 字段，缺项标「未知」）

1. 目标物（一句话，可验收）
2. 现状（文件在哪、跑到哪一步）
3. 禁止项（不改什么、不装什么、不删什么）
4. 验收（命令、截图、链接、真人走通一条路径）
5. 输入素材（路径列表）
6. 输出路径与命名
7. 分阶段 + 每阶段 commit / tag
8. 未实测声明（哪些没验证，必须标出来）
9. 何时停下来问人（触发条件，不是「遇到问题就问」）

## 两个开关

- **「先别写代码」**：默认开。需求没对齐前只输出方案与问题。
- **「可以反驳我」**：写进任务书，允许 agent 提出更省的路径，而不是顺着做。

## 反例

- 只发「继续」→ 20 轮没结束（077）。
- 正例：112「先别执行，先问我任何问题、可以反驳我」→ 一次对齐。
- 任务书没写「不改什么」→ agent 顺手重构了不该动的地方。
- 用户只说「太 AI 了 / 收敛一下」→ 空指令，先翻成可检查项（见 `voice-deai`）。
