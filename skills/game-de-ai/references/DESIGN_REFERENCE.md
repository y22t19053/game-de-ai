# DESIGN_REFERENCE — 认可案例库

> 只收录**用户认可过的**设计案例。它是艺术指导提案的引用来源，不是灵感墙。
> 未确认的条目必须标 `[候选]` 并写清「待确认什么」，不得当作依据使用。

## 收录格式（一条案例 = 一个文件头 + 4 个字段）

```md
## <名称> · <类型：游戏/电影/书封/网站/唱片…> —— [已确认|候选]
- 来源：<URL 或作品名 + 平台 + 年份；本地图路径>
- 视觉特点（可证据化）：<3–5 条，写颜色/材质/构图/字体，不写形容词>
- 值得借鉴的具体设计：<1–3 个可以直接搬的方法，例如「标题压在出血的色块上，字被裁掉 15%」>
- 适用场景：<什么题材/什么界面用得上>
- 可迁移方法：<抽象成一条规则，例如「用裁切制造未完待续感」>
- 不适用/风险：<在哪些情况下会翻车>
```

## 使用规则

1. 提案时至少引用 1 条 `[已确认]` 案例；一条都没有时，明说「本次无认可案例，方向仅基于题材推导」，并在交付时请用户确认案例。
2. 引用的是**方法**，不是外观。写清「我要迁移的是它的什么」。
3. 同一个方法不能在所有项目里重复用——第二次使用要说明为什么它仍然适合这个题材。
4. 新案例入库前必须问用户一句：「这个进案例库吗？」没有确认就留在 `[候选]`。

## 自产实拍（2026-11-15，三案并置，供迁移方法，不代表用户已认可）

### 四、B「值班台」·《小泽模拟器》主案 —— [候选]
- 来源：`little-zelensky-simulator/visual/preview/menu-1440x900.png`、`game-1440x900.png`
- 视觉特点：近黑木桌 + 唯一左上光源；纸 `#e3d5b6` 占 35–45%；红 `#9d3a26` ≤3%；数字全等宽；圆角 ≤2px。
- 值得借鉴：①**先放实物光源，再谈纸**——纸的亮斑必须有来源；②主菜单与局内屏共用「物件层叠」语法（便签压账页、电报条塞进账页下）；③第五入口主动降级 13px，避免五按钮等权。
- 适用场景：档案/公文/夜间值守/单人办公桌题材；信息以「纸上条目」组织。
- 可迁移方法：**「信息 = 桌上的实物」，每个信息块必须能回答「它在这张桌子上是什么东西」。**
- 不适用/风险：光源没调好就退回「深色网页 + 纸色卡片」；台灯静物在移动端无处安放，只能隐藏。

### 五、A「档案柜」· 公文纸 + 索引表 —— [候选]
- 来源：`little-zelensky-simulator/visual/preview/alt-a-menu-1440x900.png`
- 视觉特点：纸 `#ddd3ba` 出血压住抽屉；红头双线；点线引导（dotted leader）；骑缝章压在 x=690 的折痕上。
- 值得借鉴：①**骑缝章必须与折痕互相证明**（章面吸墨不匀、盖在折上），而不是两个贴图叠加；②索引行＝序号 + 名称 + 点线 + 右注，读起来是目录不是表格；③元数据头「密级 / 卷宗 / 建档 / 状态」四格，信息密度高但不重。
- 适用场景：文献/档案/侦探/军事公文题材。
- 可迁移方法：**「用排版纪律制造真实性」——点线引导、双线、密级行，比加材质贴图更省成本也更像真的。**
- 不适用/风险：整体仍是列表；右侧若留白过大，柜体会读成黑墙。

### 六、C「电台日志」· 遥测终端 —— [候选]
- 来源：`little-zelensky-simulator/visual/preview/alt-c-menu-1440x900.png`
- 视觉特点：近黑 + 磷光绿；每行带时刻/频道/类别；右侧 dB 刻度与链路表；失败项红笔划断线；底部反显命令条。
- 值得借鉴：①**把菜单做成「正在发生的记录流」**，行为本身解释因果；②红只标失败，不标强调；③读数用真刻度（dB 表）而非数字堆。
- 适用场景：通讯/监控/科幻终端/单人操作台。
- 可迁移方法：**「让界面自己在记录」——条目先发生，用户再介入，比「列出选项等你选」更有现场感。**
- 不适用/风险：磷光是现成套路（容易变成 Fallout 风戏服）；中文等宽缺字会破坏节奏；信息密度偏高，新手要学。
