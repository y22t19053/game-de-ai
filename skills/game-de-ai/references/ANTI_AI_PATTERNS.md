# ANTI_AI_PATTERNS — 反 AI 视觉规则

> 用途：这是可执行的检查表，不是审美评论。每条格式固定：**现象 → 判断 → 替代方案 → 合理使用空间**。
> 判断口径统一为一句：**AI 味 = 没有理由的默认值**。同一个元素如果用得有理由、且只在这一次出现，就不算 AI 味。
> 用法：设计时按 §2 选替代方案；截图后按 §3 逐条打勾；返工只改不过项。

## 1. 十一条规则

### R1 机械居中构图
- **现象**：标题、按钮、说明、图标全部沿垂直中轴对齐；页面只有一个居中的卡片。
- **判断**：如果去掉一半元素页面依然成立，说明没有视觉重心，只是排版填充。
- **替代**：
  - 用 3:5 / 2:7 的非对称网格，主内容压在 1/3 线上；
  - 让一个元素故意出血（超出容器 24–64px）或跨到下一列；
  - 次要信息贴边（`left: 6%`）+ 主视觉压中心偏左，制造张力。
- **合理使用**：启动页、对话框、单一结论页可以居中——但要有至少一个非居中锚点（角标、页脚线、印章）。

### R2 统一圆角卡片泛滥
- **现象**：所有内容都是 `border-radius: 12px` 的白/深色卡，`box-shadow: 0 4px 12px rgba(0,0,0,.1)`。
- **判断**：三种以上不同信息层级共用同一 radius + 同一阴影，且卡片之间没有结构差别。
- **替代**：
  - 一个界面最多一种「实体面板」（有边框/材质），其余用分隔线（`1px` 半透明）、留白（`32–48px`）、叠压（`translate(-4px,-4px)`）分组；
  - radius 分级：容器 0–2px，按钮 2–3px，圆形徽章 50%，有机形状用 `clip-path`；
  - 阴影改方向性硬影：`box-shadow: 4px 4px 0 var(--ink)`（印刷/贴纸感），或干脆不要阴影，靠底色差分离。
    硬偏移阴影是**有条件允许**项（Impeccable 判为 advisory）：只有当 `ART_DIRECTION.md` 写明「印刷/贴纸/neobrutalist 世界」时才用，全项目只允许一种硬影语言；否则视为默认值删掉。
- **合理使用**：移动端触控卡片、需要明确「可点击区域」的列表项——但整屏只能有一类。

### R3 塑料质感 / 过度干净
- **现象**：纯色面 + 均匀柔光；没有噪点、没有边缘磨损、没有色差。
- **判断**：把画面缩到 25% 看，是否像矢量模板？放大到 200% 看，是否有任何像素级质感？
- **替代**（至少叠两层）：
  - 纸/布底：`background-image: url(noise.svg)` + `mix-blend-mode: multiply`，透明度 3–6%；
  - 边缘：`inset 0 0 0 1px rgba(0,0,0,.18)` + 四角 1–2px 的磨损（SVG mask 或伪元素）；
  - 油墨：文字用 `text-shadow: 0.5px 0.5px 0 rgba(255,255,255,.25)` 模拟套印；
  - 颗粒：`filter: url(#grain)` 或 SVG `feTurbulence baseFrequency=.8 numOctaves=3`。
- **合理使用**：高科技/无菌题材（实验室、太空舱）可以干净，但干净要有「精确感」：等宽数字、毫米级对齐、单一冷光源。

### R4 渐变背景与装饰阴影
- **现象**：`linear-gradient(135deg, #667eea, #764ba2)`；发光按钮；无来源的柔光球。
- **判断**：渐变是否对应真实光/空间？说不出来源就是装饰。
- **替代**：
  - 单色底 + **一处** radial 光（`radial-gradient(ellipse at 30% 0%, rgba(255,200,120,.14), transparent 60%)`），模拟唯一光源；
  - 用色块并置代替渐变过渡（硬边、套色偏移）；
  - 阴影只给「真的被光挡住的东西」，方向与光源一致。
- **合理使用**：天空、屏幕光、烟雾等真实体积介质；游戏内 CRT/全息界面（要有扫描线与色散配合）。

### R5 标准化排版（无层次）
- **现象**：字号 12/14/16/18 均匀递进，全部 400 字重，行高统一 1.5，没有字距变化。
- **判断**：把所有文字换成黑色方块，读者能否分出主次？分不出就是平的。
- **替代**：
  - 字阶用跳跃比例：`1.25`（紧凑）或 `1.5`（戏剧化），至少有一级跨度 ≥2 倍；
  - 同屏最多 3 个层级：主张（48–96px）/ 支撑（16–20px）/ 元信息（11–12px，字距 +0.08em，全大写或小型大写）；
  - 用字重和字距做对比（900 + +0.12em 对 400 + 0），不要只靠字号；
  - 允许一处「不合规」的排版：竖排标题、超长单行、被裁切的大字。
- **合理使用**：数据表格、设置页等工具型界面可以均匀，但要靠对齐和数字等宽建立秩序。

### R6 模板图标 / 素材 / 插画
- **现象**：一套 `stroke-width:2` 圆头线性图标；通用扁平人物插画；AI 生成的「精致但无特征」半写实图。
- **判断**：这些素材换到另一个同题材游戏是否毫无违和？是则不合格。
- **替代**：
  - 自绘 6–8 个图标，统一「笔压」但不统一形状（1px 抖动、非完美圆）；
  - 混媒介：手绘线条 + 一枚印章 + 一个像素/网点图标，只要它们属于同一世界观；
  - AI 图必须过调色与颗粒（见 `ASSET_WORKFLOW.md` §3），并把主体剪影改成可辨识符号。
- **合理使用**：系统级设置、退出确认等「世界外」界面可以用中性图标。

### R7 视觉密度平均
- **现象**：每个区块高度相近、间隔相同，页面像表格展开。
- **判断**：页面有没有一处「密到需要停下来读」和一处「空到能呼吸」？
- **替代**：
  - 按 60/30/10 分配空间：主视觉 60% 面积，信息 30%，留白 10%（极端时可到 40% 留白）；
  - 制造一次节奏突变：密区用 8–12px 间距，疏区用 64–120px；
  - 用一件「大物件」（角色/场景/大数字）当视觉锚，其余信息退到边缘。
- **合理使用**：结算/报表页可以密，但要靠分组和层级而非均匀网格。

### R8 缺乏主次、节奏与冲突
- **现象**：所有元素亮度/饱和度接近；没有焦点；滚动下来每屏都一样重要。
- **判断**：眯眼看，第一眼落在哪里？第二眼？如果散开就是没有焦点。
- **替代**：
  - 每屏一个主角：饱和度最高或明度反差最大的区域只能有一个；
  - 引入一次「冲突」：冷暖对撞、粗细对撞、正负空间对撞（如大面积暗底 + 一小块高亮纸）；
  - 用遮挡和景深制造前后关系（前景压角、背景降低对比）。
- **合理使用**：过场/加载页可以不设焦点，但要有明确的时间感（进度、呼吸、等待的具象化）。

### R9 所有项目共享同一设计语言
- **现象**：不同游戏都用同一套暗色 + 霓虹蓝 + 圆角卡 + 同一字体。
- **判断**：把两款游戏的截图并排，2 秒内分不出→不合格。
- **替代**：每款游戏定「指纹三件套」并写进 GAME_DNA：① 一个专属色（含 hex 与占比）② 一种字体组合 ③ 一个图形母题（印章/裂痕/网点/波浪/网格），三件套在不同游戏间不得复用。
- **合理使用**：同一系列（续作、DLC）可以共享三件套中的一件，作为系列签名。

### R10 过度安全 / 保守 / 平滑
- **现象**：所有边界圆润、所有动效 ease、所有颜色低饱和、所有文案四平八稳。
- **判断**：有没有一个「我会犹豫要不要保留」的细节？没有就是太安全。
- **替代**：
  - 每件作品留一个「受控的错误」：套印偏移 1–2px、贴纸翘角、扫描线、手写批注、故意不齐的基线；
  - 动效换曲线：默认**不用**过冲/回弹（反射式 bounce 本身就是 AI 味）；机械感用 `steps(6)`，瞬切用 0ms，自然减速用 `cubic-bezier(.16,1,.3,1)`；确需过冲时只限单次、非高频交互（如一次性开箱）；
  - 「受控的错误」优先由套印偏移 1–2px、贴纸翘角、基线不齐、扫描线承担，而不是靠曲线炫技；
  - 允许一个区域高饱和到「有点刺眼」，其他区域退让。
- **合理使用**：可读性受法律/平台要求约束的界面（健康提示、支付页）保持常规。

### R11 换材质不改结构（伪归档 / 伪复古）
- **现象**：把列表或卡片换成纸色、压一层纸纹、盖个章、换个衬线字——结构仍是「一个矩形里排条目」。缩到 25% 与任何后台管理页同形。
- **判断**：25% 缩略图里，它是「某个应用的内容列表」还是「这款游戏里的一件东西」？前者＝只换了皮。
- **替代**：
  - 改**信息组织本身**：行 → 格、列表 → 桌面物件、菜单 → 正在发生的记录流；让「位置、占用、顺序」自己承载语义；
  - 材质只做**证据**（阴影落在哪、折痕怎么过、盖章与折痕互相证明），不做主角；
  - 参考 `DESIGN_REFERENCE.md` 案例 A：点线引导 + 骑缝章压折痕，比再加一层纹理更省成本也更像真的。
- **合理使用**：设置页、内部工具这类「用户只想快速找到一项」的界面，保留列表结构是对的——不是所有列表都要革命。

## 2. 替代方案速查（做设计时先从这里选）

| 想要的效果 | 不要用 | 用这个 |
| --- | --- | --- |
| 分组 | 圆角卡 + 阴影 | 分隔线 + 留白 + 一处实体面板 |
| 主次 | 加大字号 | 明度/饱和度反差 + 面积占比 |
| 质感 | 高斯模糊/发光 | 噪点、纤维、套印、边缘磨损 |
| 空间 | 居中 + 网格 | 出血、叠压、非对称网格、景深 |
| 情绪 | 紫色渐变 | 单一光源 + 色温统一 + 局部高饱和 |
| 动效 | fade + slide 0.3s | 分层 stagger + 物理曲线 / 瞬切 |
| 图标 | 线性圆头套件 | 自绘混合媒介 + 母题统一 |
| 文字层级 | 均匀字号 | 跳跃字阶 + 字重/字距对比 |

## 3. 截图自检（每轮预览后逐条打勾，不过就返工）

在看截图前先做三件事：① 缩到 25% ② 眯眼 ③ 只给 3 秒。

- [ ] 缩到 25% 还能看出这是什么游戏？（辨识度）
- [ ] 眯眼看得出第一焦点？第二焦点？
- [ ] 有没有一处明显留白 + 一处明显密集？
- [ ] 圆角/阴影/渐变各有理由？能不能各删掉一个？
- [ ] 有没有一处「不可能是默认值」的细节？
- [ ] 字体层级是否 ≥2 倍跨度？是否只靠字号区分？
- [ ] 素材是否同一光照方向、同一颗粒强度？
- [ ] 换成另一款同题材游戏，这套画面还成立吗？（成立 = 不合格）
- [ ] 有没有一个你自己都犹豫的细节？没有 = 太安全。

**计分**：9 项里 <7 项通过 → 不进下一步；7–8 项 → 允许进入素材/实施；9 项 → 冻结为当前基准。

## 4. 反例（来自真实返工）

- 只给「太 AI 了」就改三版 → 每次都在猜。应先定位到具体规则（R2/R5/R7），一次只改一层。
- 把「反 AI」理解成「禁用圆角/禁用渐变」 → 得到另一种模板（粗暴暗黑风）。反的是默认值，不是元素。
- 一次同时改配色 + 字体 + 构图 → 无法判断哪项有效，且推翻用户已认可的部分。

## 5. 阈值与评分（不重复抄，指读）

- 精确阈值（对比度 ≥4.5:1 / 字阶 ≥1.25× / 行高 1.5–1.7 / 间距 4-pt / 动效四档 / 强调色 10% 面积）：`references/impeccable/CORE_RULES.md` §0。
- 可判定的反模式清单（kicker、卡片套卡片、渐变文字、无源发光、hero-metric、章节编号、icon-tile-stack 等）：同上 §8。
- 评审打分：Nielsen 10 项 ×0–4 = /40，真实界面多在 20–32；严重度 P0–P3；认知负荷 8 项（每组 ≤4、可见选项 ≤4）：同上 §9。
- 交付闸门 12 项：同上 §10；本文件 §3 的 9 项截图自检是它的「游戏版最小集」。
- 冲突时以 `ART_DIRECTION.md` 为准，并在 `DESIGN_LESSONS.md` 记裁决。

## 6. 与 Impeccable 的四处裁决（已生效）

| 项 | 统一口径 |
| --- | --- |
| 硬偏移阴影 | 有条件允许：方向写明「印刷/贴纸」才用，一种足矣，否则删 |
| 过冲曲线 | 默认不用；受控错误改由套印/翘角/基线不齐承担；仅单次、非高频可用 |
| 发光 | 判定句统一为「这光从哪来」：能说出光源合法，说不出即装饰 |
| 字体禁令 | 不照搬 Inter/Roboto 禁用；改为「字体必须写进 GAME_DNA 指纹三件套并给出理由」，否则视为默认值 |
