# PERSONAL_TASTE — 个人审美档案

> 这是本 skill 的第一输入。每次创作开始先读它，创作中用它做取舍，交付后按用户反馈回写。
> 只记录「用户确认过的判断」和「带置信度标记的推断」。不写通用设计常识。

## 0. 怎么用 / 怎么回写

- 动笔前：读 §1 五条主张 + §3 偏好清单 + §4 反感清单，写出本次要守的 3–5 条。
- 提方案时：每个方向必须能对上一句「它满足哪条主张、避开哪条反感」。
- 交付后：用户说「就这个 / 不对」时，把**具体视觉事实**回写到对应条目（见 §6 格式）。
- 置信度标记：`[已确认]` 用户明说过；`[推断]` 我从用户选择里总结的，用前确认；`[待验证]` 只是假设。

## 1. 五条审美主张（本 skill 的宪法）

1. **独立视觉身份优先于精致度。** 宁愿一张粗糙但有主张的画面，也不要一张干净但谁都能做的画面。
2. **要看得见人类决策的痕迹。** 每个界面至少有一个「不可能是默认值」的选择：错位的印章、手写批注、故意露出的纸张边缘、不齐的字距。
3. **辨识度优先于安全。** 允许不完美、允许局部刺眼、允许非标准布局；但不允许「说不出为什么」。
4. **跨游戏必须不同。** 两款游戏截图并排放在一起，2 秒内要能分出是两款游戏（判断依据：颜色、字体、母题三件套）。
5. **材质与氛围优先于干净与平滑。** 画面要有物理世界的痕迹：纤维、颗粒、油墨、划痕、光照方向；塑料感和无缝渐变是减分项。

## 2. 审美坐标（用前先看，实际项目要重新落点）

| 轴 | 倾向 | 置信度 |
| --- | --- | --- |
| 粗糙 ↔ 精致 | 偏粗粝，但要「受控的粗糙」：纹理可辨、结构清楚 | [已确认] 部分 |
| 手作 ↔ 工业 | 偏手作：纸、墨、印、雕刻痕迹 | [推断] |
| 暖 ↔ 冷 | 视题材；无主题时不默认冷色科技感 | [推断] |
| 密 ↔ 疏 | 极端混合：一处极密，一处大面积留白；反对均匀 | [已确认] 反感均匀密度 |
| 明亮 ↔ 阴沉 | 偏中低调，暗部保留颜色而不是死黑 | [推断] |
| 写实 ↔ 抽象 | 抽象但要可指认（剪影/符号/几何母题），不要无意义装饰 | [推断] |

## 3. 偏好清单（具体到可执行）

- **色彩** `[已确认]` 反感全屏渐变与装饰性阴影；`[推断]` 喜欢「大面积低饱和 + 小面积高饱和」；暗部用带色相的深色（如 `#1a1410`），不用纯黑。
- **字体** `[推断]` 中文正文字体不要默认思源黑一路到底；标题可用有笔锋/印刷感的字体，正文可读性优先；允许衬线 + 无衬线混排，但要定好各自职责。
- **版式** `[已确认]` 反感绝对居中的机械构图；`[已确认]`（2026-11-15 《小泽模拟器》旨意原话「更像一份被翻过的档案，而不是一个网站」）反感**网页式首屏**——主菜单不该长成卡片列表；`[推断]` 接受明显的不对称（3:5、2:7 这类比例），但信息仍要能顺着读。
- **组件** `[已确认]` 反感统一圆角卡片；`[推断]` 喜欢「一个界面里最多一种实体面板」，其余用分隔线、留白、叠压组织。
- **素材** `[已确认]` 重视素材质量与统一性；`[推断]` 接受 AI 生成图，但必须统一调色与颗粒，否则一眼假。
- **动效** `[待验证]` 倾向「少而准」：进场分层出现、交互有明确物理反馈（压、弹、咔哒），反对整页 fade-in。
- **信息展示** `[推断]` 喜欢把数据做成「世界内物件」（账本、收据、档案卡、监控画面），而不是悬浮 UI 卡。

## 4. 反感清单（红线，来自用户原话）

1. 方正、规整、绝对居中的机械构图。
2. 无差别使用统一圆角卡片。
3. 过度干净、塑料质感、缺乏材质细节。
4. 千篇一律的渐变背景和装饰性阴影。
5. 缺乏层次的标准化排版。
6. 模板化图标、素材和插画。
7. 视觉密度过于平均。
8. 页面缺乏主次、节奏和视觉冲突。
9. 所有项目共享相似的设计语言。
10. 视觉表达过度安全、保守、平滑。

> 红线不是「禁用元素」，而是「禁用默认值」。圆角、渐变、居中本身没错，错在没有理由、每个项目都这么做。判断口径见 `ANTI_AI_PATTERNS.md`。

## 5. 协作偏好

- **要方案对比，不要一个答案。** 至少 2 个实质不同的方向，最好 3 个；差异要在一级轴上（媒介、时代、情绪、抽象度），不是换个配色。
- **关键决策留给人。** 艺术方向、主色、字体气质、UI 隐喻由用户拍板；执行细节我来定。
- **一次只改一层。** 反馈「太满」就只动密度，不要顺手改配色和字体。
- **说人话。** 不用「高级感」「氛围感」「呼吸感」当理由，换成可检查的描述（留白比例、明度差、纹理强度）。

## 6. 回写格式（追加到 §3/§4 或 DESIGN_LESSONS）

```
- [已确认] <视觉事实> —— 证据：<哪次项目/哪句话>，日期 YYYY-MM-DD
- [推断] <总结> —— 依据：用户在 A/B 里选了 B（B 的特征是…）
```

回写原则：只写用户明确认可/否决过的；一次最多加 2 条；新条目与原条目冲突时，改原条目并注明「2026-11-15 修订」。
