# UPSTREAM_RESEARCH —— 文案去 AI 味的上游调研与授权结论

检查日期：2026-11-15（六份 README + 六份 LICENSE 均读到原文，非搜索摘要）
用途：GAME DE-AI V0.2「中文游戏文案去 AI 味」模块的方法来源与复用边界。

## 0. 一句话结论

**没有一个仓库可以整包搬来当游戏文案工具**：它们都是英文写作/通用中文应用文导向。
真正能落进本技能的是五条**机制**——密度阈值、覆盖率回执、表面/结构双层、weak-alone 聚合、三级强度。
本技能只吸收机制与判定逻辑，**不复制任何仓库的文件与规则原文**，因此只在下面标注「需保留声明」的地方承担归属义务。

## 2. 逐个仓库：它到底解决了什么

### #1 daydayup-xq/zh-humanizer（MIT，溯源不清）
- 能力：中文精简与「说人话」，单文件融合式提示词。
- 值得借：篇幅守恒律（改写前后长度落在 **4/5–5/4** 区间）、按文体三分（叙述/说明/口语）给不同规则。
- 不复用理由：版权人姓名空白，README 的 clone 地址指向另一仓库（lian-xiao/zh-humanizer），文本出处无法确认。

### #2 blader/humanizer（MIT，约 69k star）
- 能力：26 条模式分 A–F 六组，五段流程（识别→诊断→改写→复核→事实核对）。
- 值得借：**强度分层**（hard / strong / soft）与 **weak alone 的聚合判定**——单条弱信号不作为判决，但三条同时出现就升级为问题。这正是中文「三点排比 + 形容词堆 + 升华结尾」的判定方式。
- 也借：区分文体再套规则；事实锁定合约。

### #3 davidcogan/avoid-ai-writing（MIT）
- 能力：把 AI 痕迹分成**表面层**（词、标点、句式）与**结构层**（论证与组织）。
- 关键证据：只清表面痕迹，质量只从 95.5 回升到 93.9（+1.6），论文 arXiv:2604.03136。
- 结构层五类（本技能改造为游戏文案版）：①证据够了还反复解释 ②复杂结果压成单一原因 ③无视反证下定论 ④同一条身体感官线索反复表达同一种情绪 ⑤无来源的宽泛断言。
- 采用方式：**结构层改动要显式授权**（会动到内容组织，可能超出「只改文案」的边界）。

### #4 shir-danishyar/humanize（MIT）
- 能力：39 条模式同时服务「生成」与「改写」两个方向；四种语域；`voice-profile.md` 落盘；确定性 linter。
- 值得借：**密度而非绝对禁用**——`hits per 1000 words`，默认阈值 5，超阈值退出码非零，可进 CI。
- 也借：**误报白名单**（不报 `in order to` 这类人类高频表达，报了反而把文本推向 AI）。
- 也借：词表按年份分代（2023 / 2024 / 2025）——英文词汇漂移快；中文侧对应的是「平台腔代际」（小红书体/电商体/客服体）。

### #5 davidvictor/slopspeare（CC-BY-4.0）
- 能力：`rules.json` 规则库，稳定 ID（`PUNCT-1` / `RHET-1` / `VOCAB-2` / `SUBST` / `STRUCT` / `TONE` / `FORMAT` / `REVISE` / `HEAD`），可被脚本选择器过滤。
- 最稀缺的两件：**覆盖率回执**（每条规则都必须被明确判定，回报「共查几条 / 各档命中几条 / 有几条不适用」）与**三级 strictness**（hard-ban 直接禁止 / strong-default 默认避免但可解释后回退 / guideline 只是提醒）。
- 也借：三遍审法（机械层 → 语境层 → 全文层）、编辑契约（改什么、不改什么、谁签字）。

### #6 syw2039/humanizer-zh（MIT + NOTICE）
- 能力：36 组中文平台腔模式，把 #2 的英文方法中文化。
- 值得借：**NOTICE 范式**——继承上游版权人，另写一份说明「本仓库是改编版、改了哪里」。这是中文化改编最省事也最诚实的合规写法。
- 局限：14KB 单日建仓、无测试无 lint，只能当目录用，不能当实现。

## 3. 跨仓库归纳

**六家都在做、值得直接学的**
1. 事实锁定合约（数字/名称/引文不得被改写污染）：6/6。
2. 模式编号 + before/after 样例：6/6。
3. 分级（强度或密度）而非绝对禁用：4/6。

**真正稀缺的（本技能吸收的就是这三条）**
1. **覆盖率回执**（#5）：中文模式一旦超过 20 条，模型必然抽查三条就收工。只有「逐条判定 + 回报计数」能治。
2. **表面/结构双层，结构层需授权**（#3）：游戏文案的「假」大多在结构层——同一情绪反复写、信息够了还解释、复杂结果压成单一原因。改词救不回来。
3. **密度阈值 + 确定性 linter**（#4）：把「像不像 AI」变成可数的指标，而不是审美争论。

**中文与英文的差异（决定本技能不能照抄的地方）**
| 维度 | 英文 | 中文 |
|---|---|---|
| 主要指纹 | 词表（delve / landscape），随年份漂移快 | 句式与篇章：三点排比、「不仅…更」、连接词堆积、强行升华、客服捧哏 |
| 标点信号 | em dash 每 145 词 > 1 | 破折号/省略号/顿号连排 |
| 稳定性 | 词表需要持续更新 | 四字格与套话跨模型稳定，可长期复用 |
| 可移植部分 | — | 结构层（与语言无关） |

结论：**本技能的中文模式库必须自建**（见 `CHINESE_AI_PATTERN_CATALOG.md`），上游的价值集中在机制层。

## 5. 未做与不做

- 未安装上述任何仓库，未把它们的规则文本嵌进本技能。
- 未采用它们的英文词表（对中文游戏文案无判别力）。
- 未把 AI 检测器分数当验收标准（用户任务书明确禁止）。
- 上游若后续变更许可证：重新核对 §1 表，优先 MIT，放弃限制商业用途的仓库。
