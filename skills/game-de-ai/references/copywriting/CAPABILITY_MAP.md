# 文案能力清单与调用关系（copywriting）

**状态：2026-11-15 冻结。** 四环节（诊断 / 局部改写 / Voice Profile / 复核）作为当前可用模块，按需调用；不新增部门、审批流程、评价体系，也不做 AI 检测器集成、一键全文重写、跨项目统一禁用词表、自动金句。重新评估只在出现真实项目需求 + 可复核证据 + 合理收益时进行（冻结范围见文末 §四）。

四环节是并列能力，不是流水线——按需取其中一段，别每次都跑全套。

```
                    ┌──────────── 项目自己的材料（工程里的真实字符串）
                    │
  ① 诊断 Diagnosis  │  读到原文位置 → 指认模式/结构/事实问题 → 给"改或不改"的建议
        │           │  支撑：CHINESE_AI_PATTERN_CATALOG.md（P01–P46）、GAME_COPY_TYPES.md（十类预算）
        │           │  机械排雷：scripts/copy_scan.py（G01–G13，只排雷，不判美）
        ▼
  ② 改写 Rewrite    │  三档：局部修正 / 句内重写 / 段落重组（结构层要先要授权）
        │           │  支撑：COPY_DEAI_GUIDE.md（六问 + 生成时预防 + 三档 + 保护表）
        │           │  硬约束：事实与占位符原样保留、不补写无依据事实、篇幅守恒 4/5–5/4（预警）
        ▼
  ③ Voice Profile   │  每款游戏/每个声部一份 → templates/COPY_VOICE_BIBLE.md
        │           │  只由该项目材料与明确决策生成，不套用别的项目的文风
        │           │  长度规则必须实测语料（V0.2 两次凭空定字数的教训）
        ▼
  ④ 复核 Review     │  对照：事实有没有丢、语义有没有漂、角色性格有没有变、是否长出新模板
                    │  支撑：templates/COPY_REVIEW.md（含覆盖率回执与误报登记）
```

## 一、能力表

| 环节 | 能做什么 | 现状 | 证据 | 不该用它的时候 |
|---|---|---|---|---|
| ① 诊断 | 指到「文件:行」，说明是结构层还是表面层问题，给"改/不改"建议 | 可用（手工为主 + 扫描器辅助） | `VALIDATION_2026-11-15.md` 8 条 | 只有一句文案、且类型不明（先定类型再诊断，否则误判） |
| ② 改写 | 三档改写，最小改动优先；结构层改动需授权 | 可用 | 同上，5/8 条实改 | 原文质量已合格（本轮 3/8 判"不改"） |
| ③ Voice Profile | 建/维护每款游戏的文风档案（声部、句法指纹、长度区间、禁用表达） | 可用（模板 + 实测方法） | `bistro-rush/visual/v02_test/COPY_VOICE_BIBLE.md`、浮生牌同名文件 | 没有该项目语料时（不许凭空模仿） |
| ④ 复核 | 查事实丢失、语义漂移、新模板化；记误报 | 可用（模板 + 回执口径） | `templates/COPY_REVIEW.md`、C-001/C-002 法庭实测 | 当"AI 检测器分数"用（不作标准） |
| 支撑·机械扫描 | 长度预算、连接词、客服/宣传腔、占位符登记 | 可用 | `scripts/copy_scan.py` 实测 8 条：flagged=2（1 真 1 类型误判） | 当美学判决、当验收门槛 |

## 二、调用关系（三条实际路径）

- **小修**：①诊断 → ②局部修正 → ④抽查。不建 Voice Profile，不动档案。
- **整款对齐**：③建 Voice Profile（先量语料）→ ①批量诊断 → ②句内重写 → ④复核 + 覆盖率回执。
- **生成阶段预防**：开工六问（类型/读者/位置/情境/谁在说/玩家要得到什么）→ 直接写 → ④复核。**这条最省事，优先用它**。

## 三、给其他项目的最短用法（复制到自己的对话框）

```
用 game-de-ai 的文案能力，只处理玩家可见文字，不改玩法/数值/剧情。
1) 先按 references/GAME_COPY_TYPES.md 给每条标类型（button/label/toast/tutorial/dialogue/item/shop/ending/notice）。
2) 有语料就先建 COPY_VOICE_BIBLE.md（长度区间必须实测，别凭感觉写字数）。
3) 诊断：指到 文件:行，说是结构问题还是用词问题，给"改/不改"。
4) 改写：最小改动优先；要动段落结构先问。
5) 复核：事实/占位符/角色性格/新模板四项，给出覆盖率回执。
禁止：补写无依据的事实、把两款游戏改成同一种腔、用 AI 检测器分数当标准。
```

## 四、已知缺陷（不值得开发的功能也列在这里）

1. **扫描器召回低**：母版复用、三段套、客服腔都抓不到（本轮 2 条漏判），它只适合排雷。
2. **类型错配会成批误判**：`--type` 必须按条目标注，批量套一个类型会把优质文本打回。
3. **没有自动语料统计**：长度区间目前靠人跑脚本量（`_research/v03_corpus/corpus_stats.py` 是临时件，未进技能）。
4. **不建"通用文风库"**：不同游戏必须各自立档，这是设计选择，不是缺失。
5. **不建议做的**：AI 检测器集成、一键全文重写、跨项目统一禁用词表、自动生成"金句"。
