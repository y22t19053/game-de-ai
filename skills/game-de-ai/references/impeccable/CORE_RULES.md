# Impeccable 核心规则（提炼版）

> 源：`pbakaus/impeccable` @ `2b86d9c0`，skill v4.9.1 / engine v0.1.24，Apache-2.0。原文出处见 `SOURCE.md`。
> 提炼口径：每条都能落成一个**设计动作**或一个**可判定的检查项**。判定标记：
> `[看]` 看成品渲染（截图可判）｜`[算]` 读计算值/量像素｜`[读]` 读代码｜`[问]` 问用户。
> 强度标记：**【禁】** 默认禁止（brief 明确要求可赎回）｜**【绝】** 无例外｜**【必】** 必须做到。
> 适用边界：§0–§7 适用于游戏内 UI（HUD/菜单/结算/设置）与宣传物料；标 `[Web]` 的条目针对浏览器渲染，
> 不套用于 3D 场景内美术与引擎内嵌贴图。**不适用于**：字体选型禁令中的「品类默认字体」一条（游戏可用专属字体），
> 以及 §8 中标注 `[网页]` 的页面级规则。

## §1 层级：先证明「一眼能排出来」

1. **【必】squint test** `[看]`：把截图缩到 25% 并模糊，仍能按顺序认出「主 → 次 → 大组」才算成立。认不出 = 无焦点，返工。
2. **【必】skeleton test** `[看]`：把文案全换成灰块，仅靠层级与图形母题，这节还能说出「这是什么」吗？说不出 = 你一直在靠文案撑设计。
3. **【必】单焦点** `[看]`：每屏只有一个主角（饱和度最高或明度反差最大的区域只能有一处）。最强色必须拥有一个明确区域或角色，不许撒碎钻。
4. **【必】层级靠三件事** `[读]`：字号、字重、字距三者至少动两个；只靠字号区分 = 平。
5. **【禁】平均密度**：不许每个区块高度相近、间隔相同。必须有一处「密到要停下来读」与一处「空到能呼吸」。
6. **【必】proximity 优先** `[读]`：先用间距分组，不够再加容器。加容器是最后手段。
7. **【必】间距二值化**：密区与疏区用两档明确不同的值（例：8–12px vs 64–120px），不要在中间找一个折中值。

## §2 排版

8. **【必】字阶要用得出来**：相邻级差 ≥1.25×，且至少有一级跨度 ≥2×（主张 vs 支撑）；层级数 3–4 个字号、2–3 个字重。
9. **【必】正文行长 65–75ch**（prose 允许 45–75ch）；>80 字符换行失败。行高与行长反相关：行越宽，行距越大。
10. **【必】标题 `text-wrap: balance`** `[Web]`，正文 `text-wrap: pretty` `[Web]`（消末行孤字）。
11. **【必】标题节奏** `[算]`：渲染后上方间距必须大于下方，否则标题漂移、读不出归属。
12. **【禁】skipped-heading**：h1 直接跳 h3 等跳级。
13. **【禁】全大写正文**：≥80 字符的句子式全大写判违规（短标签、单数/缩写、logo 不算）。
14. **【禁】正文宽 tracking**：>0.05em 只许用于短元信息标签。
15. **【必】暗底浅字三维补偿** `[看]`：暗底浅字比亮底深字显得更细更散，须略加行高、略加 tracking、必要时加一档字重。
16. **【必】只用到的字重/子集** `[读]`：不加载用不到的 900、斜体全集；给字体配 metric-compatible fallback（中文尤其要查豆腐块与回退后行高变化）。
17. **【必】段落节奏二选一** `[读]`：段距 或 首行缩进，不许都上。
18. **【禁】系统 display 字体当自有世界的 display voice**：Impact、Arial Black、平台 sans 当标题字体。「最接近的已装字体」是失败不是回退——改字体栈或自绘。
19. **【禁】把 monospace 当「技术感」戏服**：只用于代码/数据/度量（等宽数字合法，代码字体当正文不合法）。
20. **【禁】Unicode 字形/emoji 顶替图标系统** `[看]`：图标必须真画，统一笔画与字重。`★ ▸ ⚙ 🎮` 这类字符不算图标系统。
21. **【必】标签光学对齐** `[看]`：`text-box: trim-both cap alphabetic` 要加在**承载文字的 label 元素本身**；inline-flex 按钮里的文字是匿名 flex item，加在按钮上到不了它——用 `span{display:block}` 兜住。trim 过后仍可能视觉偏低，必须看渲染结果再微调。

## §3 布局与间距

22. **【必】有文档的间距刻度** `[读]`：4-pt 基准（4/8/12/16/24/32/48/64）。纯 8-pt 会缺 12 这种必要的中间档。
23. **【禁】monotonous-spacing**：整屏一个间距值刷到底 = 平。
24. **【必】容器内边距** `[算]`：有边框或底色时 ≥8px（12–16px 更好）；贴边的文字框是最常见的廉价信号。
25. **【必】视口安全距** `[算]`：正文离视口边缘 ≥16px，建议 24–32px；≤480px 视口允许收到 ≥12px。
26. **【禁】edge-flush-cards / first-viewport-column-overflow**：卡片贴边、首屏列溢出容器。
27. **【必】响应式要结构性** `[看]`：重排、收拢、回流、揭示之一；不是只缩字号。每个断点用**真实文案**跑一次并修溢出。
28. **【必】同组件跨上下文用 container query** `[Web]`；兄弟元素节奏优先用 `gap`，不要逐个 margin。
29. **【必】触控目标**：视觉标记可以小，可点区域必须够用（移动端 ≥44×44px 物理区域）。
30. **【必】深度只在澄清状态或层级时用** `[看]`：阴影要带 offset + 柔 blur；零 offset 的彩色光晕是装饰不是深度。
31. **【必】光学修正只在看过渲染之后做** `[看]`：不猜。
32. **【必】区域的媒介由内容决定，不由可实施性决定** `[问]`：人物/产品/机械/带透视的插画/按名字命名的材质（织物、纸纹、皮革、拉丝金属）= 必须用 raster；文字、控件、chrome、可数图表、平面形状系统、必须响应缩放的 = semantic。把雕花面板写成 CSS、用多顶点 clip-path 做撕边，是对已定案的**静默删除**。

## §4 颜色

33. **【必】建角色，不建色板** `[读]`：canvas/抬升面、主次文字、action·focus·selection、border/分隔、success·warning·error·info、数据类别。先有角色再有 hex。
34. **【必】色相从产品含义与视觉方向选，不从品类联想选** `[问]`：「科幻→青色」「恐怖→血红」是品类默认值，必须能说出为什么是**这个**色。
35. **【必】新调色板优先 OKLCH** `[读]`：亮度/chroma 可预测地调。派生 ramp 时接近白/黑处要降 chroma，不要为数学整齐在极端亮度保持高 chroma。
36. **【必】彩色面上的次要文字** `[读]`：从该色相或前景色派生（更深或更亮），**绝不**用通用灰。alpha 会把对比度绑到背后内容上，宁用显式颜色也别叠半透明。
37. **【必】主 action 的色不许花在装饰上**；语义色保持稳定且尊重平台/领域惯例（红色既可能是危险也可能是 HP）。
38. **【必】数据不能只靠颜色** `[看]`：亮度/chroma/形状/标签/图案至少再叠一个通道。
39. **【必】暗色模式必须显式设计** `[看]`：表面抬升与对比度要单独定，**禁止机械反相**浅色主题。
40. **【禁】ai-color-palette**：紫→蓝紫渐变、暗底青色、暗底霓虹 + 第二个 tell 色相；`#667eea→#764ba2` 是典型。
41. **【禁】cream-palette**：暖米/奶油色当整屏底色当默认值。
42. **【禁】gradient-text**：渐变文字。强调靠字重或字号。
43. **【禁】decoration glow**：零 offset 彩色 halo、`radial-halo`、`radial-spotlight-glow`、暗底彩色模糊阴影；以及装饰性 glass/blur。光必须有来源，能说出光源才合法。
44. **【禁】gray-on-color**：彩色底上用灰字（改用该色的更深/更亮派生）。
45. **【限】有机轮廓** `[看]`：不许用几何 mask（圆形/多边形/径向渐变）近似照片主体边缘；近似 = 廉价版，不如不做。
46. **【禁】埋掉的图** `[看]`：图片被 ≥0.9 alpha 蒙层或近零 opacity 盖住（包括「装饰性背景图」）。

## §5 动效

47. **【必】一个有作者意图的瞬间** `[看]`：整页一个有理由的动效，不是散落效果，也不是每段都同一个入场。
48. **【必】从已可见的默认态出发做指数 ease-out** `[读]`：内容默认必须可见——脚本失败不能藏页面（`content-hidden-at-rest` / `script-error`）。
49. **【必】时长按功能分档** `[读]`：100–150ms 即时反馈 / 150–300ms 常规状态 / 300–500ms 布局·浮层·视图 / 500–800ms 刻意署名的焦点入场。**出场比入场快**。
50. **【绝】bounce/elastic**：不要反射性用过冲曲线；自然减速用 `cubic-bezier(0.16, 1, 0.3, 1)`。需要机械感用 `steps()`，不要用回弹。
51. **【必】hover 时元素自己不动** `[读]`：让子元素承载位移（`.card:hover .card-surface{transform:translateY(-2px)}`），因为自己被位移会从指针下溜走并闪烁。hover 预览的 `transition-delay` 只设在 hover 态，离开时不延迟。
52. **【禁】动 layout-driving 属性**：width/height/top/left/margin；用 FLIP / transform / grid。`will-change` 只在已知动画窗口内加。
53. **【必】每个动画都要 `prefers-reduced-motion` 路径** `[读]`：reduced motion = 更少更温和（削弱空间位移，保留承载意义的 opacity/color/state），**不是全关**。
54. **【必】非必要循环在离屏/隐藏时停** `[读]`；`pulsing-dot`、`blinking-cursor`、`marquee` 默认禁。

## §6 状态（缺一即不合格）

55. **【必】状态清单** `[看]`：hover、focus-visible、disabled、loading、error、empty（含真实内容）、控件可用、响应式构图。
56. **【必】empty 要区分五种成因**：首次使用 / 无结果 / 被筛选掉 / 无权限 / 加载失败。同一条「暂无数据」覆盖五种 = 用户无法恢复。
57. **【必】loading 说明真实操作**；有真实进度就显示；**绝不编造进度**（假进度条、假百分比）。
58. **【必】hover 预览不阻断**：预览不许遮住主内容、不许改变布局。

## §7 文案与反馈

59. **【必】状态消息四层** `[读]`：此刻唯一要知道的事实 → 可用的下一步 → 改变决策的上下文 → 语气。每层都有内容才写。
60. **【必】一个意思只说一次**：标题已说明状态的，导语要么加新信息要么删掉。
61. **【必】标签描述会发生什么**，不描述触发手势（「删除存档」而不是「点这里」）。持久 label 必须在，placeholder 只当示例。
62. **【必】破坏性动作**：命名对象与后果（「删除 slot-3 的存档」）；**能 safely undo 就优先 undo 而非二次确认**。必须确认时，消息与按钮都写动作名，**禁用 Yes/No/OK/Submit**。
63. **【必】错误三答**：什么失败了 / 为什么（已知且有用时）/ 怎么恢复或还剩什么替代。内部错误码不许当主消息。
64. **【禁】marketing-buzzword** `[看]`：streamline、empower、supercharge、world-class、enterprise-grade、next-generation、cutting-edge（中文对应：赋能、一站式、极致、丝滑、重新定义）。
65. **【禁】aphoristic-cadence** `[看]`：3+ 段落都以短反驳句或「不是 X。是 Y。」式警句收尾——这是文案层面的 AI 指纹。
66. **【禁】theater-slop-phrase**：空转的宏大句（「设计不只是……，更是……」）。删掉不损失信息。

## §8 反模式清单（62 条检测规则的可用子集）

> 全部 62 条见 `SOURCE.md` 指向的 `antipatterns.json`；这里只留**可在游戏 UI 截图/CSS 上判定**的部分。
> slop 类 = 「像 AI 生成」的信号；quality 类 = 「不像人做的成品」的硬缺陷。
> **判定强度**：62 条里只有 18 条带 `severity` 字段 —— 16 条 `advisory`（只会提示，不让扫描失败）、
> 2 条 `error`（`script-error`、`content-hidden-at-rest`）；**其余 44 条默认是 primary finding**（≠0 退出码）。
> 自建检查时照此分级，否则会把「建议」当「失败」，评审结论失真。

67. **【绝】kicker-above-heading**：标题上方的小标签/eyebrow/chip。**任何 brief 都救不回来**，直接删，标题自己承重。
68. **【禁】同尺寸 icon+标题+正文的卡片阵列当页面结构**；**卡片里套卡片（nested-cards）永远错**。
69. **【禁】hero-metric 模板**：大数字 + 小标签 + 支撑数据 + 强调色。
70. **【禁】章节编号 01/02/03**（除非编号本身携带读者需要的信息）。
71. **【禁】不需要打断/不需要保护焦点时用 modal**。
72. **【禁】side-tab / border-accent-on-rounded**：卡片/列表/提示上 >1px 的彩色 border-left/right；圆角元素配单侧彩边。
73. **【禁】icon-tile-stack**：圆角方形图标块压在标题上。
74. **【禁】italic-serif-display**：Fraunces / Recoleta / Playfair / Newsreader 的 italic 当 hero 标题。
75. **【禁】shape-assembled-illustration**：用基本图元（矩形/圆/三角）在 inline SVG 里拼「场景」当插画。
76. **【禁】sparkline / 进度环 / 软阴影圆角矩形** 冒充内容。
77. **【禁】gpt-thin-border-wide-shadow**：1px 极淡边框配大面积柔阴影。
78. **【禁】repeating-stripes-gradient / codex-grid-background**：条纹渐变底、网格背景板。
79. **【限】overused-font**：Inter / Roboto / Fraunces / Geist / Plus Jakarta Sans / Space Grotesk。**游戏可用专属字体**——本机使用时改为「默认值检查」：字体必须有理由，不能是「最顺手那个」。
80. **【限】hard-offset-shadow（advisory）**：位移 ≥4px 且 blur=0 的硬阴影（`box-shadow:4px 4px 0`）。上游措辞很克制：
    它是「review prompt，不是 AI 作者的证据，也不要求自动删除」——**可能**属于有意的 neobrutalist 方向。
    本机用法：只在方向文件写明「印刷/贴纸/neobrutalist 世界」时用；否则视为默认值，删。
81. **【限】oversized-h1 / extreme-negative-tracking**：整句标题用 display 尺寸；tracking 低于 -0.04em。
82. **【禁】broken-image / text-overflow / text-occlusion**：图 404、文字溢出、文字压字（`clipped-overflow-container` 同类，但上游标 advisory）。
83. **【禁】repeated-container-text**：同一容器内同一文案出现 3+ 次（模板占位没换）。
84. **【禁】justified-text** `[Web]`：两端对齐（CJK/泰/阿拉伯等字符网格对齐文字不受此限）。

## §9 评分与严重度（评审时用）

85. **10 项 Nielsen 启发式各 0–4 分，满分 40**：状态可见性、系统与现实匹配、用户控制与自由、一致性与标准、错误预防、识别优于回忆、灵活高效、美学与极简、错误恢复、帮助与文档。
86. **区间**：36–40 Excellent（只需 polish，可发）/ 28–35 Good / 20–27 Acceptable / 12–19 Poor / 0–11 Critical。**诚实打分：真实界面多在 20–32**。有 n/a 项时按百分比读（90%/70%/50%/30%），且**绝不把 /40 印在部分集合上**。
87. **严重度**：**P0 Blocking**（完全阻断任务，立刻修）/ **P1 Major**（显著困难或困惑，发布前修）/ **P2 Minor**（有 workaround，下轮修）/ **P3 Polish**（无真实用户影响）。拿不准就问「用户会为此联系客服吗」，是 → 至少 P1。
88. **认知负荷 8 项**：单一焦点、分块（每组 ≤4 项）、分组、视觉层级、一次一件、最少选择（≤4 个可见选项）、工作记忆（≤4 项）、渐进披露。失败 0–1 项 = 低；2–3 = 中；4+ = 高危。
89. **评审要指定 persona** `[问]`：急躁老手 / 困惑新手 / 无障碍（键盘+屏幕阅读器）/ 压力测试（边界数据）/ 单手移动+被打断。按界面类型选 2–3 个，不许泛泛「用户会觉得」。

## §10 交付前闸门（12 项，缺一不可）

90. `[看]` 25% 缩略图 + 眯眼：主次顺序仍成立。
91. `[算]` 正文对比 ≥4.5:1，大字/控件 ≥3:1，且彩底上没有灰字。
92. `[读]` 字阶相邻 ≥1.25×，全文只有 3–4 字号、2–3 字重。
93. `[算]` 正文 14–16px 起、行高 1.5–1.7、行宽 ≤80 字符、tracking ≤0.05em。
94. `[算]` 间距走 4-pt 刻度，且有明显的密/疏两档；标题上方 > 下方。
95. `[看]` 没有 kicker、没有卡片套卡片、没有渐变文字、没有无源发光、没有 emoji 顶图标。
96. `[看]` hover / focus / disabled / loading / error / empty 六态齐全，empty 分对了成因。
97. `[读]` 动效时长在档位内、无 bounce、有 `prefers-reduced-motion` 路径、默认态内容可见。
98. `[看]` 破坏性动作命名了对象与后果；能 undo 的没强上二次确认。
99. `[算]` 每个断点用真实文案跑过，无溢出/压字/贴边。
100. `[读]` i18n 预留 30–40% 膨胀，用了逻辑属性。
101. `[看]` 25% 缩略图能认出是**这一款**游戏（不是任何同题材游戏）。
