# 完整模拟：《夜航气象站》一次帝制走场

> 用途：这是机制的**参照实跑**。第一次用帝制流程、或不确定某一步写到多细时，照这篇的行文密度与数字颗粒度写。
> 性质：机制验证用的完整走场，不是可交付设计稿。项目纯虚构，人名、数据均为推演。
> 项目：1974 年北方沿海两人值守气象站。玩家是夜班观测员，一整夜按时辰读表、发报、判断是否叫醒站长。
> 平台：桌面 1440×900、移动 390×844。本次只重构主菜单。
> 凡写"约"处是待实测项，已收进 §十二 待验证。

## 御旨（原始输入，逐字）

> 「我想做一个 1974 年北方海边气象站的游戏，玩家是夜班观测员。主菜单现在是深色卡片列表，像任何一个网页。你帮我重新想一下视觉。」

判读：诉求不是换皮肤，是"主菜单不要像网页"。这是身份级重构，不是配色调整。

## 一、承旨分流

| 判定项 | 事实 | 结论 |
| --- | --- | --- |
| 改动范围 | 主菜单版式 + 素材 + 材质 | 超出"单点修改" |

**判为「重大艺术方向」→ 走三省。** 不进"小修直办"通道；该通道只允许改字号/间距/对比度这类不动构图的动作。

## 二、内阁访谈（3 轮，每轮只问 1 个）

| 轮 | 只问这一个 | 皇帝原话（保留犹豫、否决、生活联想） |
| --- | --- | --- |
| 1 | 这一夜，玩家最怕的一件事是什么？ | 「怕漏报……也说不好，怕睡过去吧。以前我爸在变电所值夜班，说后半夜人是木的。**别给我做成恐怖游戏那种调子，我不想吓人。**」 |
| 2 | 主菜单上必须能看见的，最多说三样。 | 「时间、下一个要发的报、还有……我是不是该叫站长了。就这三样。**别加成就、图鉴那些**，设置放角落小字就行。」 |
| 3 | 第一次打开，你希望他先注意到哪一块？ | 「嗯……玻璃。窗上的玻璃吧。我姥姥家冬天玻璃全是霜，得哈气才看得见外面。**但你要是做得像贴上去的图，我就不干了。**」 |

由此立的硬约束（后文全部受其约束）：

1. 情绪目标是"困、但要撑住"，不是"怕"。禁 jump scare，禁持续低频（>-20dB、>2s）。
2. 主菜单只允许 3 个信息项：时间、下一个报点、叫醒站长。设置收成 11px 小字，不做入口卡片。
3. 玻璃必须 raster 且过统一层四关；CSS 渐变冒充玻璃＝直接判废。

| 材质纹理 | 磨砂玻璃（raster）+ 指纹与哈气擦痕（SVG，blur .6px）+ 木窗台（raster）。 |
| 美术素材方向 | 3 张 raster（结霜玻璃层、海面夜景、窗台木纹）+ 2 张自绘 SVG（窗框、器物轮廓）。 |

## 五、门下省独立议论

逐条判四问（模板化／只是精致／有更狠的表达／忽视题材自带资源）：

| 案 | 是否模板化 | 是否只是精致 | 有更狠的表达吗 | 忽视题材资源吗 |
| --- | --- | --- | --- | --- |
| A | **是**。行式列表 + 右留白＝任何笔记/档案应用 | **是**。换纸纹理的 list | 有：把"行"改成"格"，占用本身成为动作 | 部分。用了纸和章，没用"必须在固定时刻做完" |
| B | 否。窗是本题材独有的观看关系 | 否。有代价（牺牲居中可读性） | 已在用 | 否。窗、霜、海都在 |
| C | 否，但码表可能变炫技 | 否 | 有：报文比 UI 更能表达"准确" | **部分是**。1974 手写观测簿本身就是现成字形资源 |

### 封驳：驳回案 A 的版式主体

**驳「单列行式台账 + 右侧 38% 留白」。** 这一处会退回模板：行高 72→76px、栏线换 1px 灰，它就是任何 archive 应用的内容列表。行的语义就是"列表"，等于只给网页换了一层纸。换纹理不改结构，是把模板化推后一层，不是消除。

替代动作（可执行，不是建议）：

1. 行 → 格。版心改双栏印刷表格：栏宽 148px + 剩余，栏线 1px `#23211c`、opacity .38。
2. 菜单项＝一个格子的整块热区（≥48×48px），不是整行；选中态＝该格盖 12mm 骑缝章。
3. 章从装饰改为状态指示器：章的位置就是当前项，不再另做高亮色。

### 中书省复议（回一次）

接受 1、2。部分保留 3：盖章会与表头那枚固定的"当班章"撞车，两个红章同屏分不出状态。

**修订案 A′**：保留双栏格 + 整格热区；选中态改为「该格右下角起 1px 墨线 + 底色加深 4% 明度」；章只留一枚、固定表头、不参与状态。门下省接受 A′，但记一条未决项送御前奏议。

## 八、皇帝裁决

> 「B 的构图，C 的材质。台账那个先不要了，太像档案网站。手写体……别太潦草，我认字慢。」

| 决定 | 内容 |
| --- | --- |
| 采纳构图 | B：满幅出血 + 竖梃 x=37% + 右下 2:3 重心 |
| 采纳材质 | C：连续孔纸的撕裂边 + 打点墨渗透，只用于窗台告示与设置区 |
| 否决 | A 整体（含 A′），理由"像档案网站"＝模板化未消除 |
| 追加约束 | 手写楷体只用于 ≤6 字标题；超 6 字改宋体 |

合成结果：**B 的空间 + C 的墨**（纸带只作窗台一张小告示，面积 ≤8%）。冲突点：B 是 raster 主导、C 是 SVG 主导，二者颗粒强度必须收敛到同一张噪点层（opacity .04）。

## 十、工部实施

### 颜色 token

| token | 值 | 用途 | 占比 |
| --- | --- | --- | --- |
| `--glass` | `#16211f` | 主背景（玻璃外） | 52% |
| `--room` | `#241d16` | 室内暗部 | 18% |
| `--lamp` | `#d9a05b` | 钨丝灯受光面 | 10% |
| `--frost` | `#cfd8d4` | 霜线与选中描边 | 3% |
| `--ink` | `#1c1b18` | 纸带打点墨 | 7% |
| `--paper` | `#efe7d2` | 窗台告示 | 8% |
| `--danger` | `#a8352a` | 仅发报机故障指示 | 2% |

对比校验：`--frost` on `--glass` = 9.8:1；`--ink` on `--paper` = 12.1:1；`--lamp` 上放小字仅 3.1:1 → 只许 ≥24px。

### 字体栈

```css
--font-num: "OCR-B", "DIN Alternate", ui-monospace, "Consolas", monospace;
--font-hand: "LXGW WenKai", "Kaiti SC", "KaiTi", serif;    /* 仅 ≤6 字标题 */
--font-body: "Source Han Serif SC", "Songti SC", serif;    /* 正文 14px/1.6 */
```

数字全用 `tabular-nums`；手写标题 tracking `-0.02em`、字号 24–40px；正文 tracking `0`。

## 十一、御前预览（两轮）

**第一轮（1440×900）**

> 皇帝：「玻璃像贴了张手机壁纸。霜都堆在边上，中间太干净了。」

改三处：① 结霜权重 边缘 12% → 38%，另叠一张雾面层 `opacity .42`、`mix-blend-mode: screen`；
② 加 2 条哈气擦痕（SVG 路径，`#1a2422`、blur .6px、不透明度 .18）压在标签左侧；
③ 窗框投影由 `0 8px 24px rgba(0,0,0,.55)` 改为 `-6px 10px 18px rgba(0,0,0,.5)`，对齐室内灯 35° 方向。

**第二轮（1440×900 + 390×844）**

> 皇帝：「好多了，但移动端那三个标签挤成一列了，像菜单。」

再改两处并判定通过：① 竖屏三张标签沿玻璃左下角阶梯叠放（每张偏移 12px,-8px），保斜角差 ±2°，不做竖排；
② 移动端手写标题 28 → 24px、正文 14px 不动，新增 390×844 专属结霜裁切图（重裁不重出）。

判定：**通过**。依据：25% 缩略图能认出"窗"；三条律全过；两轮共改 5 处，均在构图/材质层，未动色彩体系。
