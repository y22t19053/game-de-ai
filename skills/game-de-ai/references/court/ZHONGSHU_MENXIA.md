# 中书省与门下省 · 独立议事规则

两个省是这套机制里唯一能真正拦住「AI 味」的地方。中书省负责**提出制度不同的做法**，门下省负责**在动手前把它打回去**。

## 第一部分 · 中书省：三案起草

### 一、三案不是三种风格，是三种信息制度

| 案 | 出发点 | 它改变的是 | 典型风险 |
| --- | --- | --- | --- |
| **A 题材契合型** | 这个题材在现实里由什么物件承载信息，就照着那套物件组织界面 | 材料的可信度 | 容易做成「复古拟物」摆设，信息效率低 |
| **B 大胆实验型** | 找一个非常规的组织原则（一页纸、一条流、一整面墙、一个设备面板），让界面服从它 | 信息与空间的关系 | 用户第一次上手会迷路；可实现性要验 |
| **C 跨领域融合型** | 从游戏之外借一套成熟语言（出版排版、工业面板、气象图表、唱片内页、建筑平面） | 排版与符号系统 | 借错语言会变成「贴皮」 |

### 二、每案必须写满 12 个字段

| 字段 | 要求 | 不合格示例 |
| --- | --- | --- |
| 1 命题句 | 一句话：**信息**是**什么物件**上的**什么痕迹** | 「暗黑复古风」 |
| 2 信息组织 | 信息按什么顺序排列（时间/优先级/空间/工序） | 「按重要性排」 |
| 3 构图骨架 | 主结构（如 5:3 不对称 / 满屏流 / 单页对折 / 三栏表格） | 「简洁大气」 |
| 4 字体体系 | 标题/正文/数字各自的字族与字号级差 | 「用衬线体」 |
| 5 色板 | 3–4 个色值 + **面积占比** | 「冷色调」 |
| 6 材质与光影 | 材质来自什么真实材料，光从哪来 | 「加一点纹理」 |
| 7 素材类型 | 需要哪些素材、什么形态（照片/线描/SVG/程序化） | 「找些图」 |
| 8 空间关系 | 层叠/压盖/出血/留白比例 | 「有层次」 |
| 9 视觉签名 | 一眼能认出是哪款游戏的**一个**记号 | 「整体风格统一」 |
| 10 明确不要 | 3–6 条具体禁用项 | 「不要太普通」 |
| 11 成本 | 工时量级 + 素材需求 + 后续维护难度 | 「成本适中」 |
| 12 风险 | 这个方案最可能在哪里崩 | 「应该没问题」 |

**字段 5、8、12 是压力点**：不写占比、不写层叠关系、不写崩法，这一案视为未完成。

### 三、差异七维表（交案时必须自带）

```
| 维度       | A 案        | B 案        | C 案        |
| 信息组织   |             |             |             |
| 构图       |             |             |             |
| 字体体系   |             |             |             |
| 色彩体系   |             |             |             |
| 材质语言   |             |             |             |
| 素材类型   |             |             |             |
| 空间关系   |             |             |             |
```

**硬规则：至少 4 维不同，且不同的维度必须包含「信息组织」或「空间关系」之一。**
七个维度里只换了颜色和圆角的，直接退回重写，不许交门下省。

### 四、伪差异的四种识别信号（中书省自查）

1. 三案的组件清单几乎一样，只是样式不同 → 伪差异；
2. 把同一布局转 90°、或从居中改成左右分栏 → 伪差异（空间关系没变，只是镜像）；
3. 差异要靠「配色说明」才能看出来 → 伪差异；
4. 三案的截图并排放在 25% 缩略图下，认不出是三种不同做法 → 伪差异。

## 第二部分 · 门下省：独立议论与封驳

### 五、独立议事协议（防串味）

门下省的输入**只有三样**：用户旨意原文、内阁转译表、三案正文。
**不许先看**中书省的推荐语、六部意见、以及工部的可行性评估——先形成自己的判断，再允许看。

写封驳单的顺序固定为：

1. 先写「我会怎么做」的一句话立场（不评价三案，只写自己的判断）；
2. 再逐案过四问；
3. 最后才允许写「如果必须三选一，我选哪个」。

### 六、四问（每问必须有证据，不许只下结论）

| 问 | 判定依据 | 不合格的封驳 |
| --- | --- | --- |
| **Q1 是否退回模板？** | 指到具体位置：「左侧竖栏 + 右侧大卡片 = 任何 dashboard」「统一 8px 圆角 + 图标行 = 组件库默认」 | 「有点普通」 |
| **Q2 是否只是精致？** | 精致＝同一套安全语言做得更好看。指出它**没改**的那一层（信息组织？空间关系？） | 「不够有冲击力」 |
| **Q3 有没有更狠的表达？** | 必须给出一个具体的替代动作（可以是禁用某项、可以是换组织原则），并说明代价 | 「可以更大胆」 |
| **Q4 题材自带的视觉资源用了几样？** | 列出题材可用的 5 样物件/材料，数三案各用了几样，少于 2 样的要补 | 「没体现年代感」 |

### 七、封驳单格式（照抄这个结构）

```md
## 封驳单 · <项目> · <轮次>
立场：我会把它做成 ____（一句）
Q1 模板化：<案 X> 的 <具体位置> 会退回 <模板形态>；证据：ANTI_AI_PATTERNS R__
Q2 只是精致：<案 X> 没有改 <哪一层>；它仍然是 <原形态> 换了 <皮>
Q3 更狠的表达：把 ____ 换成 ____，代价是 ____；若不做，理由是 ____
Q4 题材资源：可用 5 样 = ____；A 用 1，B 用 4，C 用 2
裁决建议：<通过 / 附条件通过 / 退回重议>
封驳项：1) ____ 2) ____（每条附替代动作）
复议要求：中书省须逐条回应，不得静默删除
```

**门下省的三条边界**：不自己拍板（拍板权在皇帝）；不许用形容词当依据；不许只否不给替代动作。

### 八、复议规则

1. 有封驳就必须复议**一轮**（不设两轮，防止无限循环）；
2. 中书省逐条回应：接受改 / 接受但改法不同 / 拒绝并给理由；
3. 拒绝的理由必须给**证据**（阈值、题材事实、可实现性），不能是「我觉得更好」；
4. 复议后仍有分歧 → 原样写进奏议的「待决」，交皇帝裁决；
5. 宁可把分歧端上去，也不要私下合流成「已达成共识」。

### 九、裁决建议的三个档位

| 档位 | 含义 | 条件 |
| --- | --- | --- |
| **通过** | 三案差异真实，可直接进御前 | 七维至少 4 维不同；无 P0 模板化问题 |
| **附条件通过** | 可以用，但必须改掉 1–2 处 | 差异成立，但某一案有明显模板残留 |
| **退回重议** | 三案是伪差异，或都停在同一层安全表达上 | 差异 ≤3 维，或「信息组织」三案相同 |

### 十、门下省不得做的事

- 不得把「不符合我的品味」写成「不合格」——品味分歧交皇帝；
- 不得在三案之外自己另起一稿并要求中书省照做（那是越权起草，只能给替代**动作**）；
- 不得为了显得严格而封驳：没有具体证据的封驳一律作废，并记入 `DESIGN_LESSONS.md` 作为反例。

## 第三部分 · 一句话总结

中书省保证**三种做法真的不同**；门下省保证**这三种做法没有一种是懒惰的**。两者都做完，才轮得到皇帝挑。
