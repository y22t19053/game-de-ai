# 帝制式创意治理 · 总纲

这套机制不为「有仪式感」，只解决三个反复发生的失败：

| 失败 | 现场长什么样 | 制度上的解法 |
| --- | --- | --- |
| **模板回流** | 说了不要卡片，实施时圆角卡片、居中大标题、统一阴影又全回来了 | 门下省在**动手前**封驳；刑部把「例外」写成表，工部只按表实施 |
| **意图蒸发** | 用户说「想要冷一点、像我爸的单位」，最后做出来是深色 dashboard | 内阁追问到**具体物件**再往下走，票拟里区分「用户确认」与「AI 推断」 |
| **伪差异** | 三个方案只是换色、换字体、换装饰，核心布局同一个 | 三案必须在**七个维度**上有肉眼可见的差别；门下省专职验伪 |

历史制度只借**分工与交接**，不借称谓表演。所有称谓都是角色 id，用来让职责边界清晰、让意见可以互相冲突。

## 一、机构表

| 机构 | 回答的问题 | 权力 | 交接物 | 禁止 |
| --- | --- | --- | --- | --- |
| **皇帝**（用户） | 这个作品要成为什么 | 定方向、否方案、改取舍、直接点部门 | 旨意（可以是半句话） | —— |
| **内廷承旨**（主 Skill） | 这属于哪一类活、该谁接 | 分流、召回档案、维护上下文 | 交接单（任务类型 + 已知信息 + 下一步） | 不替用户拍板；不跳过内阁直接出方案 |
| **内阁** | 用户真正想要的是什么 | 追问、转译、扩展方向 | `PIYI`（创意票拟） | 不把 AI 的偏好写成用户的偏好 |
| **中书省** | 有哪些**制度不同**的做法 | 起草三案 | 三案卡（每案 12 字段） | 不交伪差异；不替皇帝选 |
| **门下省** | 这套方案够不够狠、像不像模板 | 独立议论、封驳、要求复议 | 封驳单（判定 + 依据 + 替代动作） | 不自己拍板；不空口说「不够好」 |
| **尚书省** | 怎么把它真的做出来 | 拆 WBS、排顺序、派六部、守一致性 | 生产计划（部门/交付物/依赖/验收） | 不改艺术方向；不越过皇帝改指纹 |
| **六部** | 我这一门该怎么落 | 按专业出方案与实物 | 部门交付（见 `LIUBU_DUTIES.md`） | 不越界抢别部门的决策 |
| **廷议** | 这个难题谁的意见更硬 | 临时合议 | 廷议纪要（分歧 + 证据 + 结论） | 不替代御前审定 |

## 二、分流：先判规模，再决定叫谁

承旨时先回答三个问题（10 秒内答完，答完再动手）：

1. 这句话里有没有**还没定下来的视觉方向**？（有 → 内阁）
2. 这个决定会**影响整款游戏的视觉身份**吗？（会 → 三省）
3. 用户是否已经明确**由谁来做、做成什么**？（是 → 直接派该部门）

| 输入类型 | 例子 | 路径 | 最短产出 |
| --- | --- | --- | --- |
| 讨论 / 提问 | 「这种纸感是怎么做的」 | 承旨直接答 | 答案 + 一句可执行建议 |
| 局部修改 | 「按钮太亮了」 | 承旨 → 单部门 | 改一处 + 截图 |
| 意图模糊的新方向 | 「我想做海边的、有点冷的东西」 | 承旨 → 内阁 → 中书 → 门下 → 御前 | 票拟 + 三案 |
| 重大方向 / 换皮重做 | 「主菜单重做，别像网页」 | 全流程（含廷议、尚书调度） | 奏议 → 生产计划 → 预览 |
| 已定方向的实施 | 「按 ART_DIRECTION 把局内屏做出来」 | 承旨 → 尚书 → 工部 | 可跑原型 + 截图 |
| 明确点部门 | 「叫兵部把布局重排」 | 直达该部门 | 该部门交付物 |

**轻量模式**：小任务只走「承旨 → 部门 → 截图」，但**交付前仍要过门下省的四问之一**（模板化判定），否则默认值会回流。

**「重大」的量化阈值**（不许靠感觉裁）：满足任一条即判重大，走三省——
1. 触及 ≥2 个身份要素：构图 / 信息组织 / 字体体系 / 材质语言 / 色彩体系；
2. 动主菜单、主视觉、HUD 版式、开场或结算这类「一眼认得出这款游戏」的界面；
3. 要新出素材（raster / SVG / 生成图）且 >2 件。

只改字号、间距、对比度、单个色值、一句文案 = 小修直办，不进朝廷。

## 三、十一步与 A–H 的对应

| 帝制流程 | 对应 A–H | 产出物 | 停不停 |
| --- | --- | --- | --- |
| 1 下旨 | A 项目理解的开头 | 旨意原话（存档不可改写） | — |
| 2 承旨分流 | A | 交接单 | — |
| 3 内阁访谈 | B 的前半 | 访谈记录 + 转译表 | 信息不足就继续问 |
| 4 中书谋划 | B | 三案卡 | — |
| 5 门下议论 | B 的后半 | 封驳单（可能要求复议一轮） | 有封驳必须复议 |
| 6 廷议 / 专业研究 | B | 廷议纪要 | — |
| 7 御前审定 | **C 方向确认** | `ZOUYI` → 皇帝裁决 | **必须停** |
| 8 尚书调度 | D 视觉规范的前半 | WBS + 排期 | — |
| 9 工部实施 | D / E / F | 规范 4 件 + 素材 + 原型 | — |
| 10 御前预览 | G 真实预览 | 截图 + `ITERATIONS.md` | 不达标回 9 |
| 11 归档 | H 经验沉淀 | `DECISIONS.md` + 审美库回写 | — |

A–H 是**工作内容**，十一步是**决策权顺序**；两者不冲突，小任务可以只借十一步的顺序不借全部机构。

## 四、交接物清单（缺一件就不许进下一步）

| 交接物 | 谁产出 | 谁接收 | 最低内容 |
| --- | --- | --- | --- |
| 旨意原文 | 承旨 | 内阁 | 用户原话，一字不改，存 `DECISIONS.md` |
| 票拟 `PIYI` | 内阁 | 中书省 | 13 字段，其中「AI 推断」必须单列；**票拟是方向卡的超集**，方向卡只能从票拟裁剪，不许反向补写 |
| 三案卡 | 中书省 | 门下省 | 每案 12 字段 + 成本 + 风险 |
| 封驳单 | 门下省 | 中书省 / 皇帝 | 判定 + 证据（指到具体设计动作）+ 替代动作 |
| 廷议纪要 | 承旨组织 | 皇帝 | 分歧点 + 各门依据 + 是否收敛 |
| 奏议 `ZOUYI` | 承旨 | 皇帝 | 三案七维对比 + 推荐 + 待决 2–3 问 |
| WBS | 尚书省 | 六部 | 部门 / 交付物 / 先后 / 依赖 / 验收 |
| 预览单 | 工部 | 皇帝 | 截图 + 本轮改了哪三处 + 未解决项 |
| 决策记录 | 承旨 | 审美库 | 一条决策一行，含 A–E 归档类别 |

## 五、闸门：每个机构最容易塌的地方

- **承旨**：把「用户还没想清楚」当成「用户已经说完」→ 闸门：旨意里有没有至少一个**具体物件/场景**？没有就进内阁。
- **内阁**：十问连发、把访谈变成问卷 → 闸门：一次一问，且上一答必须被复述后再问。
- **中书省**：三案其实是同一案换皮 → 闸门：差异七维表里至少 4 维不同，否则重做。
- **门下省**：用形容词封驳（「不够高级」） → 闸门：每条封驳必须带一个可执行替换动作与一个数字/取值。
- **尚书省**：拆完 WBS 又自己改方向 → 闸门：WBS 里每项能指回三案中被选中的那一条。
- **六部**：越界替别部门定调 → 闸门：本门交付物只改本门字段，跨门改动要廷议或皇帝点头。
- **皇帝（我）**：只给情绪不给取舍 → 闸门：御前奏议必须把选择收敛成 2–3 个**互斥**问题。

## 六、独立意见怎么保证（单模型环境下）

不假装有多智能体。用**阶段隔离 + 证据留痕**制造真实分歧：

1. **分阶段写**：门下省先只读「旨意 + 三案正文」，写完封驳单，才允许看中书省的自我辩护与六部意见。
2. **分角色写**：同一个问题按部门各写一段，禁止在一段里同时用两个部门的口吻。
3. **交叉核对**：门下省的每条封驳，都要能被 `ANTI_AI_PATTERNS.md` 的某条 R 规则或 `impeccable/CORE_RULES.md` 的某个阈值验证一次。
4. **留分歧**：廷议没收敛的分歧要写进奏议的「待决」，不许被总结成「已达成共识」。

## 七、什么时候不必惊动朝廷

- 只改一个 token 的值；
- 修 404 / 溢出 / 缺字；
- 用户已经给了完整规格（尺寸、色值、文案、结构都有）；
- 复刻已验证过的组件。

以上直接做，做完附一句「按 X 规范执行」，并进 `ITERATIONS.md`。
