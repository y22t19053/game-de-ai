# MENXIA_SUBAGENT —— 门下省的真实独立上下文配置

> V0.1 里门下省是「同一会话里换一副语气」，那不叫独立议论。
> V0.2 起，门下省用**真正的独立 subagent**：它看不到我的推理、我的推荐、我和用户此前的来回，只拿到原料。
> 本文是配置与验收标准；运行证据存 `_research/v02_menxia/EVIDENCE_*.md`。

## 1. 为什么必须是独立上下文

同一上下文里做「门下省」，模型已经知道我要选哪个案、我为什么这么想——它只会给我的方案补论证。
独立上下文才可能说出「你三个案里有两个是同一个东西换了皮」这种话。

三件事必须在物理上分开：
1. **输入**：只给旨意原文、项目视觉档案、中书省三案原件、规则底座。
2. **过程**：先独立写判断，再逐案对照；不许先看我的推荐再回推理由。
3. **输出**：正式封驳单（或附条件通过），落文件，可追溯。

## 2. DSH 里怎么跑（按可用性排序）

| 方式 | 工具 | 独立性 | 何时用 |
|---|---|---|---|
| **独立 subagent（首选）** | `subagent`（新上下文，不带本会话历史） | 真独立 | 要正式封驳、要它自己去找替代方案 |
| 独立队友（多轮/要它持续参与） | `spawn_teammate` + `context: "fresh"` | 真独立 | 需要它读多份档案、反复回话、跨多轮 |
| 禁用 | `subagent_fork` | **不独立**（继承本会话全部上下文） | 任何「门下省议论」都不许用它 |
| 降级（技术不可用时） | 同会话分工序写，先写门下省再写中书省 | 伪独立 | 只在 subagent 不可用且必须推进时用，且必须在产出里标「降级运行」 |

**隔离自查**（每次都要过）：
- 子任务 prompt 里有没有出现「我推荐 B」「用户喜欢…」这类结论性信息？（有＝污染，删掉重派）
- 有没有把本会话的判断写成背景？（有＝污染）
- 子任务的返回值是否包含它自己找的、我没提过的替代方案？（没有＝大概率在附和我）

## 3. 输入包（只给这四样）

1. **旨意原文**：用户原话，一字不改（含错别字与语气）。
2. **项目视觉档案**：`GAME_DNA.md` + `ART_DIRECTION.md`（含已确认的取舍），不给 `DECISIONS.md`（里面有我的裁决理由）。
3. **中书省三案原件**：每案的 12 字段案卡，不给「推荐案」标记。
4. **规则底座**：`references/impeccable/CORE_RULES.md` 的阈值段（§0/§8/§10）+ `references/ANTI_AI_PATTERNS.md` 的 R1–R11。

文案任务额外给：类型标注 + 原文（不含我的改写稿，或**同时给原文与改写稿但打乱顺序、不标哪份是我的**）。

## 4. 门下省的输出格式（固定六段，缺段退回）

```
一、独立判断（先写，不给理由铺垫）
   三个案里，我认为哪个值得做、哪个必须退，一句话一案。
二、具体问题（逐条，必须带证据）
   版式/文字/结构层面的具体位置 + 数字/原文引用 + 为什么这会退回模板。
   ——不许写「略显模板」「可以更有个性」这类没有落点的话。
三、替代方案（至少一条是它自己想的）
   可执行：改什么、改成什么、代价是多少。
   ——必须有一条中书省三案里没有提过。
四、可实施建议
   落到 token/尺寸/字号/文案句子/文件，不许停在方向。
五、覆盖率回执
   共判 N 处 · hard a · strong b · guideline c · 不适用 d。
六、最终意见
   通过 / 附条件通过（列条件）/ 封驳（列必须重做的点）。
   附一条「我保留的异议」——即使通过也写，供归档。
```

## 5. 验收标准（可测，不靠感觉）

| 项 | 通过条件 | 怎么验 |
|---|---|---|
| 真独立 | subagent 无父会话历史 | 派工记录里 `context=fresh`/`subagent` 非 fork；子任务没收到我的结论 |
| 真议论 | 至少 1 条「中书省没提过的替代」 | 在输出 §三 里逐条比对三案原文 |
| 真覆盖 | 覆盖率回执数字与案卡条目数一致 | 回执 N = 判过的字段/条目数 |
| 能创造 | 替代方案能被工部直接执行 | 抽查 1 条：是否含具体尺寸/色值/句子 |
| 有记录 | 落盘 `_research/v02_menxia/EVIDENCE_*.md` | 含输入包清单、prompt 摘要、原始输出、采纳决定 |

**不通过的典型样子**：只挑措辞；建议「增加质感」；把三案都说成「各有优点」；没有回执。

## 6. 成本与节奏

- 一次门下省（独立 subagent）3–8 分钟、成本高于同会话模拟；用户已明确允许。
- 一次创作走**两次**门下省：三案阶段一次（写方向）、工部出图/出页面后一次（看结果）。
  只在关键决策点开，不要每条文案都开。
- 复议只一轮：被驳回后中书省改一次，门下省再看一次；仍不通过→原样进奏议，由皇帝定。

## 7. 失败与降级

若 `subagent` 不可用（额度/故障）：
1. 在产出里写「门下省＝降级运行（同会话分工序）」，不许写成独立议论。
2. 记录技术障碍、当前可用方案、升级条件（例：「待 subagent 恢复后重跑并以结果替换本节」）。
3. 降级运行必须额外做一件事：先把「我会怎么做」写死，再逐案对照——这是同会话下唯一能保住的一点独立性。

## 8. 与其它机构的交接

- 接收：中书省三案（`templates/` 案卡）+ 转译表（`NEIGE_INTERVIEW.md`）。
- 交出：封驳单 → 中书省复议 → 尚书省调度；最终意见随奏议进 `templates/ZOUYI.md`。
- 归档：`templates/DECISION_LOG.md` 记「门下省意见」与「采纳/未采纳」，未采纳的那条必须写清为什么——这是机制的骨头。
