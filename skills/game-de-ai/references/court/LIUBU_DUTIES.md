# 六部 · 专业职责与交接接口

六部不是六个审稿人，是六个**带着自己那套专业判断进场**的角色。每部的交付物都要能被下一部直接使用，不能是「意见」。

| 部 | 一句话职责 | 主要产物 |
| --- | --- | --- |
| 吏部 | 决定这次该用谁的脑子 | 角色卡（与调用理由） |
| 户部 | 素材从哪来、能不能用、留不留得下 | `ASSET_MANIFEST.md` + 素材实物 |
| 礼部 | 这款游戏该长成什么样、凭什么 | `ART_DIRECTION.md` + `VISUAL_LANGUAGE.md` |
| 兵部 | 信息摆在哪儿、怎么排 | 布局原型 + 密度与栅格规格 |
| 刑部 | 哪些线不能越，越了怎么记 | 规范与例外表 |
| 工部 | 把它做成能跑的页面并截图证明 | 原型代码 + 截图 + 迭代记录 |

---

## 吏部 · 专业视角调配

**回答**：这次的问题需要哪种专业眼睛来看？

按需召唤（一次最多 3 个，多了会互相稀释）：

| 角色 | 介入时机 | 他会问的问题 |
| --- | --- | --- |
| 游戏艺术总监 | 定方向 | 这个决定会让玩家记住哪一件东西？ |
| 平面/编辑设计师 | 排版、表格、信息层级 | 这一页如果印在纸上，栏目怎么分？ |
| 字体设计师 | 字族选择、字重级差、中西混排 | 这套字号级差在 1.25× 下还站得住吗？ |
| 工业设计师 | 拟物、面板、仪器、材质 | 这个面板上每个凸起都有功能吗？ |
| UI 设计师 | 组件、状态、可点区域 | 六态齐了吗？空态长什么样？ |
| 插画师 | 关键视觉、图标风格 | 这套线的粗细只有一种吗？ |
| 摄影指导 | 光影、景深、氛围 | 光从哪个实物来？阴影方向一致吗？ |
| 动效设计师 | 时间感、反馈 | 这个动效 240ms 够吗，还是该更慢？ |
| 材质设计师 | 纸/金属/玻璃/油墨 | 这个材质在 2× 截图上还看得出颗粒吗？ |
| 信息可视化 | 数值、刻度、告警 | 54 和 48 的差别，肉眼能看出吗？ |
| 前端视觉工程师 | 可实现性 | 这个效果在 CSS 里怎么不打补丁地做出来？ |
| 素材策展人 | 素材筛选与授权 | 这张图的来源与许可写清了吗？ |

**交接**：给中书省一张「本此调用哪 3 个角色 + 一句话理由」；给门下省一张「哪些判断超出了我的专业范围，需要别人看」。

**禁止**：不许用「要有高级感」这类无专业内容的意见充数。

## 户部 · 视觉资源与素材

**回答**：素材从哪来、什么规格、谁的授权、能不能复用。

- **权限**：`ASSET_MANIFEST.md` 由户部维护；任何素材进页面之前必须已经在清单里（路径 + 用途 + 尺寸 + 来源 + 许可）。
- **规格纪律**：位图给 `@1x/@2x`；SVG 给 24/32 网格；纹理 ≤ 200KB；字体必须有许可结论（未知就写「未知，暂仅本机使用」）。
- **成本**：AI 生图按「张数 × 返工率」估；SVG 自绘按「图标数 × 复杂度」估；一张核心视觉图 ≈ 4–8 张候选。
- **复用**：跨游戏复用素材必须改到「认不出来」，否则身份会串。
- **素材缺口处理**：先用 CSS/程序化顶着，把缺口写进清单的「缺口」列，不要用低质图凑。
- **AI 生成物也是素材**：必须与手绘/自托管素材同一张清单；记模型与 seed，否则视为不可追溯（等于没有）。
- **授权分级**：`可商用 / 仅试验 / 待确认` 三档，写清依据（模型卡原文）；禁商用的权重不进正式发布素材。

**自检**：清单里每个「已采用」都能点开；每个「缺口」都有替代方案与决策记录。

## 礼部 · 艺术指导与视觉文化

**回答**：这款游戏的视觉身份是什么，凭什么成立。

- 维护 `ART_DIRECTION.md`（命题句 + 三案结论 + 明确不要）与 `VISUAL_LANGUAGE.md`（token、组件规格、动效曲线）。
- **考据规则**：任何「××年代感 / ××行业感」必须给出 **3 个可验证物件 + 1 条证据**（照片？实物？同期印刷品？）。给不出就降低断言强度，改说「我们借的是它的 X 结构」。
- **符号纪律**：一个项目只允许一个视觉签名记号（一个章、一条刻度、一种装订），多则变成装饰拼贴。
- **跨媒介借用**：借**结构**不借装饰——借的是分栏、留白、装订、刻度，不是贴一张做旧纸纹。

**自检**：命题句能不能一句话讲给外行听懂；色板占比加起来是 100%；「明确不要」至少 3 条且都是可检查的。

## 兵部 · 构图、空间与界面组织

**回答**：信息摆在哪儿、眼睛先看哪里、手机怎么塌。

- 产出**布局原型**：先给 2–3 个骨架（不是成品），标出视觉落点、留白带、压盖关系、出血边。
- 规格：主轴（非对称比例，如 5:3）、栅格（几栏、栏宽、槽宽）、密度（每屏信息组 ≤4）、层级（标题/正文/辅注三级字号差）。
- **禁止**居中 + 卡片阵列作为默认解；要用必须给理由（例如题材本身就是公文系统）。
- 响应式：先给 1440×900 与 390×844 两个真实断点，再决定中间是否加档；移动端一律先想「一列怎么排」，不要缩放桌面。
- **可读性硬底线**：正文 ≥16px/1.5 行高；承载信息的字号 ≥11px；对比度正文 ≥4.5:1。

**自检**：25% 缩略图下能说出「先看哪里、第二看哪里」；把内容换成两倍长度不塌。

## 刑部 · 视觉规范与设计约束

**回答**：哪些线不能越，越了怎么记账。

- 维护 token 表（色/字/间距/圆角/阴影/时长）与**例外表**：每个例外写「哪一处、为什么、谁批的、何时复查」。
- 例外不是禁令的补丁，是**有代价的许可**：任何例外必须让出一项别的（例如允许出血，就必须放弃圆角统一性）。
- 检查项：对比度、字号下限、行长（65–75ch）、间距 4-pt 刻度、动效时长四档、`prefers-reduced-motion` 路径、六态（hover/focus/disabled/loading/error/empty）。
- **一致性判定**：同一功能在不同屏必须同形；不同功能的相似外形要给区分（位置/刻度/字重至少一项）。

**自检**：`VISUAL_LANGUAGE.md` 里的常量与代码一致（改代码必回改文档）；例外表没有超过 5 条（超过说明规范错了）。

## 工部 · 美术制作与前端视觉实施

**回答**：怎么真的做出来，并证明它做出来了。

- 顺序：素材（核心 3 件先做）→ 布局骨架 → 组件 → 动效 → 响应式 → 截图。
- **实施契约**：只改 `<工程>/visual/prototype/**`；不改游戏逻辑；每个视觉常量从 `VISUAL_LANGUAGE.md` 抄，不即兴发明。
- 素材制作：优先 CSS/SVG（可维护、可 2× 清晰），位图只给「必须有颗粒/光影」的地方。
- **AI 出图**：走 `references/IMAGE_PIPELINE.md` 八步；一次跑同批 3–4 张（同 ckpt/seed 族，只换主体词），产出的每张原图与 sidecar JSON 一起入库，清单写全 `ckpt/LoRA/steps/cfg/seed/提示词文件`。**「工作流跑通」不算接入成功**，能进界面并截图才算。
- **验收只在截图里做**：1440×900 @2×（桌面）+ 390×844（移动，`--full`）；截图后自己先看一遍，再交御前。
- 迭代记录：每轮写「改了什么 / 为什么 / 采纳与否」进 `ITERATIONS.md`。

**自检**：中文字体真渲染（无豆腐块）；无横向滚动溢出；hover/focus/reduced-motion 都在；没有一处阴影是「为好看加的」。

## 文案归谁管（V0.2 新增，别都推给「写手」）

玩家可见文字没有单独一个部，按职能拆成三件事：

| 事 | 部 | 产物 | 判据 |
| --- | --- | --- | --- |
| 这款游戏怎么说话 | **礼部** | `COPY_VOICE_BIBLE.md` | 一句话身份 + 句法指纹 + 拒绝表达，且与自家其它游戏能分家 |
| 具体一段怎么改 | **工部**（执行）+ 礼部（定调） | `COPY_BASELINE/DIFF/REVIEW` | 有覆盖率回执、不补事实、占位符未动 |
| 一致性、跨屏重复、禁用表达 | **刑部** | 文案规范条目 + 例外 | 同一意思不在两处用两种说法；例外要写进例外表 |

- 改文案前必读 `references/COPY_DEAI_GUIDE.md`（六问 → 三档 → 三层）；模式判定查 `CHINESE_AI_PATTERN_CATALOG.md`（P01–P46，强度 hard/strong/guideline，**不是禁词表**）。
- 机械排雷用 `scripts/copy_scan.py`；**它零命中不代表通过**（实测：AI 味明显的 10 条 0 命中）。
- 两款以上游戏时，刑部必须做「分家检查」：遮住专有名词，仍能认出哪条属于哪款。

**自检**：任何一条改动都能回答「原文为什么不行、改后凭什么更好、有没有动到事实层」。

## 部门冲突怎么裁

固定优先级（从高到低），并写进决策记录：

1. **可读性硬底线**（刑部 + 兵部）
2. **题材事实与考据**（礼部）
3. **视觉身份一致性**（礼部 + 刑部）
4. **表现力与实验性**（兵部 + 中书省）
5. **实施成本与可维护性**（工部 + 户部）

只在前一项被满足的前提下，后一项才能成立。想为了表现力牺牲可读性 → 必须走例外表并由皇帝点头。

## 廷议怎么开

**触发**：三个以上部门意见冲突、或方案涉及整款游戏的身份、或成本超过一天。

**纪要格式**：

```md
## 廷议纪要 · <议题>
参与：礼部 / 兵部 / 工部（各一句立场）
分歧点：<一句话，说清两边到底在争什么>
证据：<每方一条可核对的事实>
未收敛：<是/否；若是，列出待决项>
建议：<交中书省整理 / 直接交御前>
```

**禁止**：轮流发言后由主持人总结成「大家一致认为」。纪要里必须保留至少一条没被采纳的意见。
