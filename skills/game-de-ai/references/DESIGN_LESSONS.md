# DESIGN_LESSONS — 经验库

> 三个分区，严格分级：**已验证**（有截图/用户确认支撑）、**阶段判断**（跑过一两轮但证据不足）、**待验证**（假设，不得当规则用）。
> 每条格式：`场景 → 做法 → 结果 → 证据`。没有证据的条目降级或删除。

## 一、已验证

### V1 光只能用柔和径向渐变，clip-path 会露出硬边
- 场景：想给台灯做一个可见光锥（梯形/三角）。
- 做法：放弃 clip-path 与伪元素硬边；光斑改用两层径向渐变叠加，纸面亮部用 `linear-gradient(118deg, …)` 做方向感。
- 结果：截图中不再出现直边三角，纸的受光变成连续过渡。
- 证据：`little-zelensky-simulator/visual/ITERATIONS.md` R2「失败留存」。

### V2 低饱和暗场里的细长静物读不出物体
- 场景：桌面空处想加一支笔/一把尺当静物。
- 做法：删掉；改用有体积的物件（杯子、文件夹叠），或干脆留空。
- 结果：删掉后画面更干净，空处不再像噪点。
- 证据：同上，R4。

### V3 绝对定位的装饰件必须在移动端断点逐个复位
- 场景：桌面舞台用绝对定位（`left:604px`），移动端出现横向溢出。
- 做法：每个装饰件在 `@media (max-width:899px)` 里显式 `position:relative; left:auto; width:100%`；用截图 JSON 的 `content.width` 验收是否等于视口宽。
- 结果：`content.width` 从 906px 回到 390px。
- 证据：`preview/menu-390x844.png` 与 `ITERATIONS.md` R6。

### V4 自托管 woff2 ≠ 有中文字形
- 场景：以为标题用的是 `archive-serif.woff2`。
- 做法：量 `hmtx`/字形数（本例 362KB、约 1400 字形、0 汉字）；在文档里写明「中文由系统 Noto Serif SC 渲染，woff2 只供拉丁」。
- 结果：跨机器复现的前提变清楚——依赖的是系统字体栈，不是那个文件。
- 证据：`visual/GAME_DNA.md` 字体行 + `ART_DIRECTION.md` §13。

### V5 门下省开真独立 subagent，一次就抓到三类硬错
- 场景：文案改写提案自评「已过三层复核」，实际没看见错。
- 做法：开 fresh subagent，输入包只给四样（旨意/档案/提案/规则），不给自评、不给 DECISIONS，要求六段结构与覆盖率回执。
- 结果：抓到 ①删掉机制语（「趁热上桌」对应 `game.ts:400` 完美判定）②自造新重复（B10 用了 `achievements.ts:42` 的成就名，而 B09 正以「跨界面消重」立论）③漏审母版（`Intro.tsx:99–104` 是三条抒情句的来源）——三条都是自查抓不到的。
- 证据：`_research/v02_menxia/EVIDENCE_bistro_copy.md`。

### V6 文风档案的例句必须带 `文件:行`，否则一定循环引用
- 场景：写 `COPY_VOICE_BIBLE` 时凭印象列「已认可例句」，其中「末班车没了」「撑了 12:34」全库 0 命中；签名例句又全部取自本次改后新句，等于用被审对象自证。
- 做法：只收既有文本，每条标 `文件:行`；改出来的新句另列「待认可」，不进已认可区。
- 结果：门下省据此否掉了整份档案（Q3），修完后才可执行。
- 证据：同上 Q3；`bistro-rush/visual/v02_test/COPY_VOICE_BIBLE.md` v2 版本表。

### V7 门下省也会错，必须留一轮复议
- 场景：它对《午夜餐厅》的替代方案是「最后一个赶稿的走了，才关灯」。
- 做法：复议时按语义判——Intro 是**开店屏**，写打烊动作方向相反，驳回并给反向理由。
- 结果：机制变成双向的（它驳提案、我驳它），而不是单向下命令。
- 证据：`COPY_DIFF.md` §〇 表第 3 行；`EVIDENCE_bistro_copy.md` §三 替代 1。

### V8 机械扫描器在两类作品上结论相反，只能排雷
- 场景：同一个 `copy_scan.py` 跑两款。
- 做法：都跑，但结论分开写——《午夜餐厅》改前改后 0 命中（AI 味在评价词与跨屏重复，词表抓不到）；《浮生牌》改前 4 命中（「不是…而是」×2、破折号×2）、改后 0。
- 结果：扫描器当「该回头看的段落」提示器，通过与否看三层复核 + 覆盖率回执 + 皇帝观感。
- 证据：两作 `visual/v02_test/COPY_SCAN.md`。

## 二、阶段判断

### [阶段性] L1 素材统一靠「后期统一层」而不是「同一提示词」
- 场景：同一游戏内多张 AI 生成图风格漂移。
- 做法：生成后统一过一遍调色阶（统一色温/黑位）+ 叠同一张噪点 + 统一边缘处理。
- 结果：待补实测证据（V0.1 原型未用到 AI 生成图，尚缺证据）。
- 还缺：一次真实的多图生成 + 用户盲选。

### [阶段性] L2 三案必须做成可截图的页面，才判得出差异
- 场景：三案只写在纸上时，「差异」很容易是形容词。
- 做法：三案各出一屏真实文案的可截图 HTML，再看 25% 缩略图。
- 结果：本次 A/B/C 三案在缩略图层面确实不同轴（公文/桌面/日志流），文字版评审时并未意识到 A 的右侧空与 C 的字距问题。
- 还缺：第二款游戏复现，才能升级为已验证。


## 三、待验证（假设）

### H1 反 AI 检查表放在「截图之后」比「设计之前」更有效
- 设计前读十条规则容易变成教条；截图后逐条打勾更容易定位问题。
- 验证方式：同一稿，先读规则再设计 vs 先设计再按规则返工，比较返工轮数。

### H2 中文标题的「字重对比」比「换字体」更能制造性格
- 假设：在只有思源黑/思源宋的可选范围内，900 字重 + 负字距 + 大字号，比换成装饰字体更稳。
- 验证方式：同一标题做三版（换字体 / 加字重 / 加字距），让用户盲选。

### H3 一处「受控的错误」比整体精致更能去 AI 味
- 假设：套印偏移、贴纸翘角、扫描线这类 1–2px 的物理错误，是辨识度提升的性价比最高手段。
- 验证方式：同一界面做 A（无错误）/ B（一处错误），让用户在 3 秒内判断哪个更像人做的。

### H4 动效时长 80/160/240ms 三档足够
- 假设：超过三档的时长体系在游戏 UI 里不可感知，反而难维护。
- 验证方式：统计返工中用户对动效的实际反馈条数。

## 升级/降级规则

- 同一做法在**两个不同项目**里都成立 → 升级为「已验证」（附两个证据）。
- 只在**一款游戏、一个尺寸**上跑通过、用户只说「行」没说过为什么 → 留在「阶段判断」，行首标 `[阶段性]`，并写清「还缺哪一条证据才升级」（例如：第二款游戏复现 / 用户在 3 秒盲选里选它）。
- 一次运行中被用户否决 → 直接移到「反例」，不要留在假设区。
- 三个月未被引用 → 删除或合并，保持本文件 ≤120 行。
