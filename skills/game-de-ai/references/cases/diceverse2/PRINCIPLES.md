# 候选可迁移原则（5 条，宁少不凑）

每条按任务要求给：原则 / 本案例证据 / 解决什么问题 / 适用条件 / 可能误判 / 是否值得纳入 GAME DE-AI / 更简单的替代。
**均标 E3（由案例推导），除非另注。**

---

## P-1 约束前置：能算的，在方案阶段就算

**证据**：三案原文没有触控约束记录；844×390 下实测 28.74 / 36.13 / 35.03 px/格，全部低于门下后来定的 44px 线（E1/E2 混合）。事后补算导致方案返工。
**解决**：把"平台/成本/性能"这类可计算硬约束，从验收挪到提案。
**适用条件**：约束可量化（像素、字节、帧率、预算）且能被方案作者自己算。
**可能误判**：把不可量化的东西（"要有质感"）也硬做成数字，导致假精确；或前置太多约束把方案压死。
**是否纳入**：**是**，但不新建机制——在既有提案/方向卡模板里加一行"已计算的硬约束（含算式）"即可。
**更简单的替代**：门下的条件里已经这么做过一次（C4），把它固化成格式即可。

## P-2 审查要有落点：条件必须能指向文件，且留回执

**证据**：门下 C1/C4 → `explore.ts:4` 注释、`global.css:65 --cell-min`、`IsoScene.ts:181` 调用（E1）；对照御批只有文字、九条条件只有一张汇总表（E1）。
**解决**：区分"意见"与"生效"——审查产出必须写成"条件 → 落点（文件:行/页面/清单） → 回执（证据路径）"。
**适用条件**：审查对象是代码/文档/资源，能指向具体位置。
**可能误判**：为了留回执而编造证据路径；或把"写了落点"当成"已验证"（落点存在 ≠ 效果成立）。
**是否纳入**：**是**，作为既有门下/法庭输出格式的三列补充，不新增角色或审批。
**更简单的替代**：直接在 `MENXIA_CONDITIONS` 类表格里加"落点"和"回执"两列。

## P-3 成熟度按"进入产物"判定，不按"下载/运行"

**证据**：L0–L4 口径（`ASSET_USAGE_REPORT.md:5`）让 ControlNet 只能记 L2（权重在盘、ComfyUI 认、无 Requeue）；D 盘资源被记 L3/L4 且有截图或测试指向（E1/E2）。
**解决**：防止"下载量/调用次数"冒充生产能力。
**适用条件**：有办法指向产物（截图、引用点、测试）。
**可能误判**：L3（玩家能看到）被当成 L4（可复跑验证）；或反过来，没有测试就一律不认，压死小项目。
**是否纳入**：**是**，但只作为 `ASSET_WORKFLOW` 里的一行判定口径，**不建等级管理制度、不设审批**。
**更简单的替代**：每个素材清单行加一列"证据位置"。

## P-4 降级优先：先保证缺件能跑，再追求完整

**证据**：`shots/table-degraded.png`（E1）、阴影 pass 收敛使 draw calls 142/160/162→86/85/117（commit `ccad0d6`，E1）；缺件时系统仍可运行。
**解决**：把"必须全部到位"改成"先有一个能看能玩的版本"。
**适用条件**：核心体验可分级（有可接受的降级形态）。
**可能误判**：降级版本被当终版交付，长期将就；或降级路径本身没人验证，出事时才第一次跑。
**是否纳入**：**是**（作为实施建议，非机制）。
**更简单的替代**：在原型阶段就明确写"没有 X 时的样子"，通常一两句话即可。

## P-5 事前审查 ≠ 事后裁决：时点决定价值

**证据**：C-006 `openedAt 2026-11-15T15:12:37Z`（本地 23:12）在生产尾声，`stage: executing`、`closedAt: null`、T01 pending（E1）；裁决只能影响下一轮。
**解决**：避免"程序很完整、但改变不了任何东西"。
**适用条件**：决策仍有可改变空间（未发布/未合并）。
**可能误判**：为了赶时点而仓促开庭，材料不全导致误判；或把事后复盘一律禁止（复盘仍有归责与先例价值）。
**是否纳入**：**是**，写成法庭使用纪律（已有 V0.2.0 停止开发的框架内），不新建机制。
**更简单的替代**：在案件登记时强制填"实施状态（未开始/进行中/已发布）"，已发布则只进复盘档。

## 不采用的两条（写出来，防止后人再提）

- **"资源审批部门"**：本案例的成功来自"采用矩阵＋L 分级"，不是来自审批。加审批只会加时延。
- **"独立审查强制多模型"**：本案例三方同源的问题，靠换模型不一定解决，靠**信息隔离**（分别给不同材料、不给对方结论）更直接；而后者不需要新机制，只需在派单时改输入包。
