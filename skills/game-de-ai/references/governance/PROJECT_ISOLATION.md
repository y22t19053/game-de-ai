# 组织边界：GAME DE-AI 与独立项目（协议 V0.1）

> 本文件是《补充协议：项目隔离、能力共享与方法论中枢独立运行》在 GAME DE-AI 内的正式落点。
> 协议原文（2026-11-15，用户下达）的要点在此，措辞以本文件为准；两者冲突时，以用户最新指令为准。

## 一句话

**GAME DE-AI 是一个方法论与工具中枢，不是一个项目组。**
它维护能力、验证能力、发布能力；它不主创具体游戏、不调度项目开发、不拥有项目最终取舍权。

## 组织架构

```
                    ┌─────────────────────────────┐
                    │  GAME DE-AI 中枢（本技能）    │
                    │  文法层 / 仪器层 / 法庭层      │
                    │  G1–G7、三省六部、独立验收     │
                    │  只做：研究·维护·验证·发布能力  │
                    └──────────┬──────────────────┘
                               │ 能力接口（按需调用，可拒绝）
        ┌──────────────┬───────┴───────┬──────────────┐
        │              │               │              │
   《午夜狂欢》     《小泽模拟器》    《浮生牌》      服装项目 / 新项目
   各自独立对话框   各自档案/工程     各自档案/工程    只在确实适用时调用
```

各项目保留：项目档案与历史决策、设计目标、视觉与文案规范、工程目录与技术方案、任务书/测试/验收、版本与运营记录。
**项目的设计权、工程管理权、日常决策权，不在 DE-AI 手里。**

## 权责边界（七条，照协议）

1. 项目负责人决定产品目标、审美方向、最终取舍。
2. DE-AI 提供方法、工具、证据与风险提示，**不拥有最终创作权**。
3. DE-AI 可以反驳项目决策，**不能擅自覆盖**项目已确认的决策。
4. 项目可以拒绝某项能力，并记下合理原因。
5. DE-AI 可以拒绝把缺乏证据的项目经验写进通用规范。
6. 法庭只处理符合既定重大争议条件的事项；**不因项目变多而扩大审查范围**。
7. 跨项目修改必须说明影响范围，不得擅自改别的项目的工程、文档或发布状态。

## 混体表述的检查与修订（2026-11-15）

按协议第八条第 3 款做了一次只读清查，范围：本技能 `SKILL.md`、`USAGE.md`。结论与动作：

| 位置 | 原表述 | 问题 | 本次动作 |
| --- | --- | --- | --- |
| `SKILL.md` 产出段 | 「产出：`<游戏工程>/visual/` 下的 GAME_DNA / ART_DIRECTION / …」 | 只写了"DE-AI 产出写进工程"，没写"文件属于该项目" | 补一句「这些文件归该项目所有，DE-AI 不持有项目管理权」；不改产出路径（路径本身是接入方式，不是所有权） |
| `SKILL.md` 目录约定 | `<游戏工程>/visual/` 整节 | 容易被读成"DE-AI 在项目里建工作区" | 节首补「由项目调用时创建；文件归项目」一句 |
| `USAGE.md` 第四节 | 「## 四、项目里会生成什么」 | 措辞把 DE-AI 当主体 | 改为「## 四、被项目调用时会写出什么（文件留在该项目）」 |
| `USAGE.md` 目录树 | `templates/ … 复制到 <游戏工程>/visual/ 再填` | 没交代归属 | 行尾加「（文件归项目）」 |

历史档案（V0.3 报告、决策收敛、法庭交付报告等）**不改写**——它们是当时的记录，协议要求"不大规模重写历史档案"。

## 过渡安排（《午夜狂欢》V12）

1. V12 任务书继续有效，不撤回、不重写。
2. V12 仍是 GAME DE-AI 的首次正式生产实战案例。
3. 实战产生的证据、问题、复盘可以回流 DE-AI（走 `FEEDBACK_INTAKE.md`）。
4. 但具体设计、资产生产、工程开发、Toy 发布**属于《午夜狂欢》项目**。
5. V12 结束后，DE-AI **不自动**接管该项目的后续版本。
6. 之后是否继续用 DE-AI，由该项目对话框按需决定。

## 禁止事项

- 为证明 DE-AI 有用而强迫项目接入。
- 为展示制度完整而增加无意义流程。
- 为扩大适用范围把非游戏项目强行游戏化。

> DE-AI 要成为「能被多个独立项目调用、能从真实项目学习、但不依赖任何单一项目才能存在」的系统。
