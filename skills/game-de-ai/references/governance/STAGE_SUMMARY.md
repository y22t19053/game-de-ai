# GAME DE-AI 阶段性总结与下一阶段路线图

日期：2026-11-15 ｜ 依据：V0.3 前沿研究 + 七轮否定、Court V0.2.0 成本报告、MISSION.md、MECHANISM_RESULTS.md、《午夜狂欢》V11/V12 实战

---

## 一、它最初要解决什么

**为什么 AI 做的游戏一看就有 AI 味，以及怎样让 AI 参与制作却不沦为模板。**

这个问题的检验对象永远是**作品**，不是 DE-AI 的架构。

## 二、架构还围着这个目标转吗

大部分是，但有一处明显跑偏：

| 观察 | 判断 |
| --- | --- |
| 文法层（G1）与仪器层（G2/G3/G5）直接指向"视觉/文案模板化" | 在轨道上 |
| 法庭（C-001/C-002）处理的是"证据与争议"，**不直接产出作品** | 工具，但成本高；只该在重大争议时开 |
| 三省六部：把"重要创作"拆成十一步、若干角色 | **跑偏**——它管的是流程完整性，不是 AI 味；而且研究证据（consensus-MAD 在主观任务上可能更差）不支持它作为默认 |
| G6 素材链：能跑，但 0 张进工程 | 在轨道上但没交付价值 |
| 文档规模：技能 44 文件 / 约 29.7 万字节 | **需要自我约束**——文档数量不是成果 |

**结论：架构大体仍围绕目标，但"制度层"比"结果层"重。** 收束动作是把制度降为按需、把仪器提到台前。

## 四、DE-AI 自身跑偏检查（具体删减建议）

| 问题 | 具体表现 | 建议 |
| --- | --- | --- |
| 为管理而管理 | 一次普通视觉任务也可能被拉进十一步 | 默认走 A–H 轻路径；十一步只在"改结构/改方向/有争议"时用 |
| 功能重复 | `shot.mjs` / `preview-shot/shot.mjs`、`copy_scan.py` / `recall.mjs` 有重叠 | 技能内保留一份，项目侧不重复造；文档里只写"用技能自带的" |
| 只有文档没有使用价值 | G7（未跑）、G4（无第二评审） | 标观察；**不许当作能力对外宣称** |
| 接入成本过高 | 新项目要读 8 份 references + 5 份 court 文档 | `CAPABILITY_INTERFACE.md` 一页够用；深层文档只在需要时翻 |
| 独立审美变统一模板 | 存在这种风险（token 语言容易被套到别的游戏） | 已有"一款游戏一个身份"铁律 + 反馈门槛（两项目复现才升级） |
| AI 味检测变机械指标 | 曾经把召回数量当成绩 | 已写明"不作验收、不作 KPI" |
| 更简单的替代 | G4 可直接问用户；G7 可隔天自己重看 | 简单替代优先，复杂机制只在它证明更好之后才用 |

**删减建议（不做新建设）**：不新增部门/角色/审批层级；十一步从默认改为触发式；G4/G7 在拿到真实数据前不写进任何"能力清单"的"已验证"栏。

## 五、G1 有/无闭合对照实验

方法：同一屏、同样文字与素材，A＝有 G1（token 闭合），B＝独立 subagent 在**禁止读 style.json / v12.css / 项目截图**的条件下自由成型；随机投币匿名成 `candidate-1/2`，由另一位 fresh subagent 盲评。原始材料 `bistro-rush/exp/g1/`（含 key、两图、评审原话）。

**结果（评审者原话摘要）**：排序 **A > B**；A「橘色只用于文字与主按钮，粉色只用于背景霓虹，两者不互抢」；B「黄色主按钮、绿色编号、粉色印章、胶带纸卡、深色玻璃导航，**五种视觉语言同时出现**」。同时评审者抓到 A 自己的两处毛病：右上胶囊/齿轮/底部三连＝网页落地页的固定组件；五个次要入口被压成同样字重的一行白字，「没有主次」。

**结论（收窄后的）**：

1. **分维结论（不得合并成"A 更好"）**：①视觉一致性——A 胜（B 出现多套语言并存）；②入口可用性——B 胜（整行可点区域 vs A 的 14px 裸文字）；③综合作品质量——**未测**，本轮没有问"哪张更想点进去玩"。
2. 它**管不到"好不好用"**：B 的五个入口是带箭头的整行可点区域，比 A 的一行白字更好按；A 的"安静入口"是作者取舍，不是 G1 的产物。
3. 成本不对称要说清：A 花了 3 轮返工 + 为暗幕新增 `scrim` token + 写 exceptions；B 一次成型 8 分钟，但留下五语言并存、编号颜色前后不一、`<title>` 编码乱码。
4. **实验只做过一次、单页面、单评审**——不足以升级成"结论"，只能算一次有效观察。

## 六、路线图（按实际价值排序，不扩张）

> 只在真实项目提出需求、或下一次集中验证时才执行；本轮结束后不立即启动新的大型实验。

1. **把已有工具用在真实作品上**（**归属：各项目自己的对话框**）：接手一款游戏的一屏，用 G1+G2+G3+G5 做完，产出截图前后对照；DE-AI 不再代管。
2. **G1 复测**（**归属：DE-AI 中枢**）：换页面、换评审再跑一次；不立即启动，等下一次集中验证。
3. **G6 生产闭环**（**归属：DE-AI 中枢**）：先解决光向/描边/饱和度一致，再谈产量；不达标不准宣称素材能力。
4. **G4 第二评审**（**归属：DE-AI 中枢**）：一个人十分钟即可，否则永久保持"观察"。
5. **法庭只在出现真实争议时开**，不再主动造案。

## 七、停止做的事（禁止重复建设）

> **架构冻结（2026-11-15 生效）**：本轮之后不再新增机制、部门、角色、审批层级，也不新增大规模文档。

- 停止新增机制、部门、角色、审批层级。
- 停止为机制写新的说明文档（现有 44 份文件已足够，再写必须先删一份）。
- 停止把"跑过流程/生成过图片/写了报告"当作成果。
- 停止在没有第二位评审的情况下声称"审美判断已校准"。
- 停止把单项目经验升级成通用规范（除非两项目复现）。
- 停止在普通创作任务上跑十一步。
- 停止重新审计工具环境、重新下载模型、重造已有脚本。

## 九、三张清单

**已验证（有实跑证据）**：C1（拦 2 次真错）、C2（6 视口，一次真实回滚）、C3（2 条复用 + 1 处对比度）、C5（24h 内复用成功）、C7（两作对比 + 覆盖率回执）、C8（三轮验收抓 6 处口径问题）、E5 主菜单重构（V12 实机截图 + 预览包实测）。

**待验证（有机制、无充分数据）**：C4（无第二评审）、C6（0 张进工程）、G7（未到期）、法庭（n=2）、C1 的因果（有闭合 vs 无闭合的对照只做过一次）。

**已否决 / 应淘汰**：三省六部作为默认流程；深色玻璃面板、奶白 HUD 条、全宽白胶囊、给容器加底色、AI 纸贴直接进 2.5D 场景、伪字母招牌图、无框漂浮贴纸、统一 22px 圆角（以上见否决语料 D-01…D-09）。

## 十、一句话

**DE-AI 现在是冻结的"视觉工作台 + 检查仪器"，还不是一个"创作系统"。**
下一步不是让它更像一个系统，而是让它多做出几张能看的画面。
