> 一次决策一条，只追加不改写。这是审美库的原料：没有记录 = 这次决策下次会重犯。
> 存放位置：`<游戏工程>/visual/DECISIONS.md`（项目级）；跨项目的长期结论另抄一条到 `references/DESIGN_LESSONS.md`。

## 记录模板（复制以下块）

```md
### D-<序号> <标题>

- 日期：YYYY-MM-DD
- 旨意： 「（用户原话）」
- 分流： 讨论 / 局部修改 / 新方向 / 重大方向 / 已定方向实施 / 点部门
- 访谈发现： （一句最关键的）
- 中书省： A ____ / B ____ / C ____
- 门下省： 封驳 ____；替代动作 ____；复议 ____
- 廷议： 参与 ____；分歧 ____；未收敛 ____
- 皇帝裁决： ____（选了谁 / 混了哪几层 / 否了什么）
- 六部采用的方法： 礼____ 兵____ 工____ 户____ 刑____ 吏____
- 实际效果： 截图 `preview/____.png`；25% 缩略图能认出吗 □能 □不能
- 用户认可的点： ____
- 用户要求改的点： ____
- 归档类别： A / B / C / D / E（可多选）→ 去向：____
- 复查： 若 30 天后仍然成立 → 升级为长期偏好
```

## 归档五类（决定写回哪个文件）

| 类 | 含义 | 去向 |
| --- | --- | --- |
| **A 长期偏好** | 用户明确确认的审美判断（跨项目成立） | `references/PERSONAL_TASTE.md` |
| **B 认可案例** | 这次做出来的、用户认可的具体视觉 | `references/DESIGN_REFERENCE.md`（含截图路径） |
| **C 被拒模式** | 用户否掉的设计做法（要写清「否的是哪一层」） | `references/ANTI_AI_PATTERNS.md`（作为新 R 规则或已有规则的例证） |
| **D 已验证经验** | 可复用的制作/实施方法 | `references/DESIGN_LESSONS.md` → 已验证 |
| **E 待验证推断** | 我判断对但用户还没表态 | `references/DESIGN_LESSONS.md` → 待验证 |
| **阶段性判断** | 做出来了、也用上了，但只在一款游戏/一个尺寸上验过 | `references/DESIGN_LESSONS.md` → 阶段判断，标 `[阶段性]` 并写清「还缺哪条证据才升级」 |

**归档完成的判定**（缺一条就不算归档）：项目侧 4 份文档（`GAME_DNA` / `ART_DIRECTION` / `VISUAL_LANGUAGE` / `ITERATIONS`）与技能侧目标库**两列都打勾**。模型最常见的漏项是只更新技能库、不更新项目文档，或反之。
