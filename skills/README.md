# skills/

七个 Markdown 技能，给 AI 用，不给玩家看。它们不是「提示词合集」，是**作业规范**：每条都写着什么时候该停、什么话不可以说、什么算做完。

按一个游戏项目的生命周期排：

| 阶段 | 技能 | 什么时候用 | 一句话产出 |
|---|---|---|---|
| 动手前 | [`prompt-contract/`](prompt-contract/) | 需求只有一句「优化一下」，或要把活派给别的 agent | 9 字段任务书（目标物/现状/禁止项/验收/素材/输出/阶段/未实测/何时停） |
| 动手前 | [`project-audit/`](project-audit/) | 接手停了一阵的项目、重构前、别人说「已完成」但你不信 | 「文档 vs 现实」冲突表 + 只读检查结果，0 行改动 |
| 做的过程 | [`game-de-ai/`](game-de-ai/) | 定美术方向、做 UI、产素材、改玩家可见文案 | 视觉规范 + 真实预览截图 + 交付自检 13 项 |
| 做的过程 | [`poster-brief/`](poster-brief/) | 当天就要发的海报/封面/头图 | 4 行 brief → 出图 → 只调四层，不加元素 |
| 做的过程 | [`voice-deai/`](voice-deai/) | 文案「太 AI 味」「不像我写的」 | 逐句对照表 + 七项自检 |
| 做的过程 | [`pov-guard/`](pov-guard/) | 游戏对话与旁白、章节定稿前查视角越界 | 逐场表「角色｜已知三条｜本场需要他知道｜来源」 |
| 收尾 | [`delivery-gate/`](delivery-gate/) | 想说「做完了 / 上线了 / 能用了」 | 四问证据表（链接/外部用户/反馈/最小下一步）+ 三列处置表 |
| 收尾 | [`../court/`](../court/) | 要对「完成」这个词负责时 | 证据入卷 → 裁决留痕 → 逾期如实报红 |

## 怎么装

把想要的目录整个放进去：

- DeepSeek Harness：`~/.dsh/skills/<技能名>/SKILL.md`
- Claude Code：`.claude/skills/<技能名>/SKILL.md`（项目级）或 `~/.claude/skills/`

每个 `SKILL.md` 的 frontmatter 里写了触发词与不适用场景，agent 按它自己决定要不要加载。

## 为什么放在一起

单看每一个都像常识。放在一起才成立：**动手前把需求钉死 → 过程中只按规范改 → 收尾前先查现状 → 对外说话要有证据**。缺任何一环，剩下几环都会被「先糊过去再说」吃掉。

`court/` 是这套规范的强制版：技能靠 agent 自觉，法庭靠代码拒绝。
