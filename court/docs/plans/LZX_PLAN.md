## ② 三处排版/视觉完成度硬伤

### A. 响应式：桌面首屏被一张无限长的卡列撕开（P0，最该先修）

实测（1440×900，即设计基准）：

- `.v2-panel-ops` 高 **2903.5px**（32 张预设卡各带一个「下达」），它与 office 同排，直接把 grid 第 1 行撑到 2903.5px；
- 结果：`.v2-panel-intel` 与 `.v2-panel-time` 的 y 坐标被推到 **2983.5px**（第 3.3 屏），页面总高 **scrollH = 3400px**（3.8 屏）；
- 而 `.v2-panel-map` 只有 507.1px 高（`align-items:start`），**首屏 y=575→900 的 657×325 区域整片空场，占首屏 16.5%**；
- 更差的是 1024×768：页面 **3603px**（4.7 屏）。1280×800：**3543px**，且 ≤1280 断点把地图列降为单列后 `.v2-map-stage` 变成 **650.5×650.5** 的正方形，地图面板 847.3px 高；
- 反讽的是手机端最健康：390×844 下 `scrollW == 390`（无横向溢出）、`scrollH = 1022`。**桌面才是未完成的那一端。**

证据：`css/v2.css:125-135`（三列 grid 无行高约束）、`:282-295`（`.v2-presets` 无 max-height）、`:423-434`（1280 断点）、实测 `panels.ops.h=2903.5` / `intel.y=2983.5` / `scrollH`。

第二处响应式问题：**地图标签的字号不由字号系统控制**。`<svg viewBox="0 0 100 100">`（`js/v2/ui.js:113`）在 `aspect-ratio:1/1` 容器（`css/v2.css:174`）里等比缩放，标签声明 `font-size: 2.1px`（`:593`）：

| 视口 | svg 宽 | 折算屏幕字号 | 实测 bbox 高 |
|---|---|---|---|
| 1440×900 | 437.8 | **9.2px** | 14px |
| 1280×800 | 648.5 | 13.6px | 20px |
| 1024×768 | 508.9 | 10.7px | 15px |

最大屏反而最小（9.2px），低于 VISUAL_LANGUAGE §8 的元信息下限 11.5px；12 个地名标签挤在 437px 见方里。

## ⑤ 验收方式

1. **基线对比（已具备）**：复跑 `node _research/v020_plans/_probe.cjs`，逐项对比数字——`scrollW`@390 必须 `==390`（现通过）、`scrollH`@1440 `≤1500`（现 3400）、`intel.y` `≤760`（现 2983.5）、按钮边框对比度 `≥3.0`（现 1.52）、`:focus-visible` 的 `outlineStyle != none`（现 none）、office 面板文字左缘只允许 1 个值（现 5 个）。
2. **缩略图识别**：1440 首屏缩到 0.25×（360×225），要求仍能一眼分出「地图 / 办公室 / 行动 / 时间」四块和底部主按钮位置，**且首屏空场 ≤20%**（现 16.5% 的空场在缩略图上会被读成"资源没加载完"——比留白更糟）。
3. **双端截图**：1440×900 与 390×844 各出 game / menu 两张，人工对照 `shots/` 现有基线看差异；Edge 之外再补一次真机或 Safari 的 SVG 文本渲染（本次未测，列为风险）。
4. **回归**：`node tests/v2.mobile.check.cjs`（现成 390 溢出检查）；注意现有 `tests/contrast.test.cjs:12` 读的是 v1 的 `css/style.css`，**v2.css 目前没有任何对比度测试**，P0-2 落地时应顺手补一个（只读 token 计算即可）。
5. **发布门槛**：以上全部在 `_research` 里出 diff 与对照图，**用户确认后**才允许改 `css/v2.css` / `index.html`；正式发布由用户拍板。本计划不产生任何对正式版的写入。
