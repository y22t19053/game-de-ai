# ORD-02《午夜餐厅》按钮圆角收敛方案

- 类型：普通创作｜路径：轻量（不开庭）
- 提议人：lead｜审核：门下省日常审核｜执行：lead｜截止：2026-11-16

## 改什么（只出方案，不改源码）

现状：`bistro-rush/src/ui/styles.css` 里圆角共 **47 种**（`fp_bistro.json`），其中 `999px` 出现 33 次、`50%` 33 次、`10px` 17 次。

方案：收敛为 **2 档**
- 卡片/面板：`22px`（保留现值，不引入新数）
- 小控件（按钮、徽标、筹码）：`10px`
- 圆形（头像、圆形按钮）：继续用 `50%`；胶囊继续用 `999px`——**这两类不算"圆角种类"**，写进方案说明里避免被统计口径误判。

## 为什么

- 47 种里有大量一次性值（如 `3px`、`6px`、`14px`），是改样式时顺手写的，不是设计决定。
- 收敛到 2 档 + 2 种语义值后可读性提升，且**不改变任何颜色/阴影/字号**，风险低。

## 不做什么

- 不换色板、不动硬影 `0 8px 0`、不动字号（那是 C-003 的议题）。
- 不改源码：本项只产出 `bistro-rush/visual/v020/ROUNDING_PLAN.md`（含 grep 命令与替换清单），实施需另行批准。

## 验收

- 用 grep 复算：「非 22px/10px/50%/999px」的 `border-radius` 声明数 = 0。
- 两张截图（标题屏 + 厨房屏）重截，`git diff` 为零（只改 CSS 值时允许 0 像素变化）。
- 若任一元素出现视觉塌陷（圆形变方），回退该项。

## 判据（为什么不开庭）

可逆（CSS 单点回滚）、无实质分歧（同一设计语言内的整理）、无资源问题。
**注意**：如果审核认为「圆角收敛会牵动视觉语言」，则应 `ESCALATE` 并入 C-003，不在此单干。
