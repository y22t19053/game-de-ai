# 司法角色与权限规范（V0.1）

本文件是 `docs/DESIGN.md` 角色表的**可执行版**：每个角色写清「能做什么 / 不能做什么 / 由哪条代码强制」。凡标「靠人」的，说明该条没有代码强制，只能靠程序与验收人自觉——这类条目在 `docs/OPEN_ISSUES.md` 里另列。

## 一、角色与权限

| 角色 | 可以 | 不可以 | 代码强制（`src/court.mjs`） |
|---|---|---|---|
| **皇帝（用户）** | 定方向、混合/否决方案、要求重审、推翻先例 | —— | 无代码层（人的权力在系统之外，系统只能记录其裁决） |
| **书记员（clerk / lead 会话）** | 登记案件、登记证据、调用 CLI、封存日志 | 不得担任本案法官；不得替控辩写书状；不得自任验收人 | `JUDGE_IS_AUTHOR` / `JUDGE_IS_ADVOCATE` / `SELF_VERIFICATION` |
| **检察方** | 提交起诉书状、提出证据、交叉询问、要求补证 | 不得隐瞒对己方不利的已登记证据（**靠人**）；不得自任法官 | 书状与法官身份隔离（引擎）；隐瞒无强制 |
| **辩护方** | 提交辩护书状、回应质询、提出替代方案 | 不得自任法官；不得以「不试点」以外的空话结案（**靠人**） | `JUDGE_IS_ADVOCATE` |
| **法官** | 定争议焦点、裁证据资格、作出七种裁决之一、附条件、记录少数意见 | 不得为本案作者/控辩方；不得引用未登记证据；不得替任何一方补论据（**靠人**） | `JUDGE_IS_AUTHOR` / `JUDGE_IS_ADVOCATE` / `RULING_DANGLING_EVIDENCE` / `MINORITY_NOT_RECORDED` |
| **陪审员** | 独立投票（approve/reject/conditional）、给出理由与少数意见、写保密封存 | 不得读其他陪审文件（**靠人**）；不得在看完书状后才写初判（程序要求） | `JURY_TOO_EARLY`（阶段）/ `JURY_NEEDS_REASON`（≥10 字）/ `DUPLICATE_JUROR` / 密封哈希校验 |
| **执行者** | 交付任务、提交证据路径、写交付说明 | 不得自行验收（引擎硬拒） | `SELF_VERIFICATION` / `TASK_NEEDS_REPORT` / `TASK_NEEDS_EVIDENCE` |
| **验收人** | 核销、判 pass/fail、写 note、退回重做 | 不得是执行者本人；不得无 note 核销 | `SELF_VERIFICATION` / `VERIFY_NEEDS_NOTE` |
| **制度攻击方** | 在隔离环境攻击制度本身（伪造证据、串通、超期、诱导裁决） | 不得篡改正式档案、删证据、对外欺骗 | 隔离目录 + 审计链（`LOG_HASH_MISMATCH` / `JURY_SEAL_BROKEN`） |
| **门下省（旧机构）** | 对日常方案做封驳（普通审核） | 不得代替法庭做司法裁决；不接管重大争议 | 无代码（职责边界靠文档） |

## 二、角色切换规则

1. 同一 Agent 可跨案、跨阶段切换角色，但**必须记录**（`case.json` 的 `roleSwitches` 或审计日志）。
2. 切换后不得把一方未公开的信息带入另一方论证（**靠人**，本轮由 fresh 上下文实现隔离）。
3. 原始论证不得被切换后的立场覆盖——引擎保证：书状一经提交只能 `amend`（须给理由并留历史）。
4. 陪审不能是同一上下文复制多个投票窗口：本轮以「一陪审一 fresh 子代理 + `contextId` 记录 + 每人一份独立 JSON」实现；引擎只能校验文件名与密封，**不能校验底层是否真是独立上下文**（见 OPEN_ISSUES I-06）。

## 三、与三省六部的接口

- **法庭是横向独立审查层**，不是第四省、不是第七部。
- 三省六部继续管**日常行政工程**：中书提案 → 门下封驳 → 尚书执行核销 → 六部按需调用。
- 只有以下情形进法庭：重大争议、关键决策、权限越界、利益冲突、证据争议、严重程序违规、重大失败责任认定、推翻既有先例的申请。
- **门下省 ≠ 法官**：门下省对方案本身做封驳（内容审查）；法官管程序与裁决（程序 + 证据资格 + 判决）。同一方案不得由同一主体既封驳又裁决。

## 四、权限边界（禁止事项）

- 任何角色不得修改已封存的案卷（`case.json` 之外的 jury 文件有密封哈希，改了审计必报）。
- 任何角色不得引用未登记的证据编号（`EVIDENCE_NOT_FOUND`）。
- 任何角色不得在未裁决前派发执行任务（`NO_RULING`）。
- 任何角色不得让任务无期限（`BAD_INPUT`）、无验收标准（`TASK_NEEDS_ACCEPTANCE`）。
- 任何角色不得把「模型推论」标为「已独立验证」（`EVIDENCE_LAUNDERING`）。
