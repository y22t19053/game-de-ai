# V0.2.0 实战适配计划

**本轮只出计划，不实施。** 依据 m02252：V0.2.0 是「实战适配与验证」，之后停止集中开发、进入真实游戏改进。

## 一、V0.2.0 要证明的一句话

> 法庭只在**真实的重大设计争议**上被叫起来，且叫起来之后**有人真的按裁决执行并验收**，而不是把一个能跑的引擎再磨一遍。

## 三、范围（不做什么）

- 不新增角色（不加「实验者」「反事实研究者」等，除非有真实案件证明缺它）。
- 不改三省六部日常流程；法庭不接管日常。
- 不引入数据库/服务/框架；继续文件 + JSON + git。
- 不追求指标漂亮：不加「案件数」「按期率」这类考核指标（会立刻异化）。
- 不动 `cases/C-001`、不动小泽 V0.6.0、不发布任何版本。

## 五、失败判据（事先写死）

V0.2.0 若出现下列任一情况，判**不适配**，回退为「法庭仅作个人留档工具」，不再向下投入：

1. 两条真实案件里，裁决均未被采纳（说明程序产出的东西对创作没用）；
2. 单案人工耗时 > 90 分钟且裁决仍靠用户拍板（说明只是增加了记账工作）；
3. 出现一次「为让裁决通过而伪造证据/伪造验收」（说明制度被绕过，需要更重的取证而非更多流程）；
4. 分流判据导致几乎所有创作都被要求开庭（说明门槛写得太宽，退化成官僚）。

## 六、进入真实创作的门槛（回答用户四问之四）

满足以下三条才建议开始改两款游戏：

1. V0.2.0 的 C-003（真实争议）走完 11 步，且执行+验收都是第三方；
2. 至少一条先例被后续案件引用一次（证明先例不是装饰）；
3. 成本数字至少一栏是实测而非 unavailable（当前是 `calls`/`humanSteps`/`humanMinutes`）。

否则应该先解决第 1 条，而不是继续加制度。
