# C-004 提案：《小泽模拟器》副本里可以先做哪些视觉改动

作者：lead（提案方）｜提议开庭类型：major｜日期：2026-11-15

## 一、背景

《小泽模拟器》V0.6.0 已发布，用户已明确认可它的视觉方向（低饱和军事绿 + 档案纸 + 琥珀 + 桌面式布局），并规定：**不许推翻方向、只许小幅打磨、改动在副本或分支、正式发布需用户单独确认**。

V0.2.0 要给出一份"可执行的改动清单"，问题是清单该有多长、该不该动到身份要素。

## 二、两套清单

### 清单 A：只修硬伤（保守）

1. 移动端 390 宽下，页脚**三段**元信息（`2022.02.24 — 04.02` / `存档只存在这台设备的浏览器里` / `38 天 · 时间由你推进`）折成两行、末项孤行；`css/v2.css:569` 现为 `flex-wrap: wrap; gap: 6px 18px`（不是 8px）。【C-004 订正：原文写"两段 / 8px"系从原型误引】
2. 局内屏账页与时间条在 1024×768 下重叠 6px（截图 `game-1440x900.png` 显示 1440 无碍，需要补测）。
3. `--paper` 与 `--paper-2` 的明度差原文写作 ΔL 2.1。实测是**两对不同的色值**：成品 `css/v2.css:19-20`（`#ddd3ba` / `#cabfa3`）ΔL* **7.19**、对比 **1.23:1**；原型 `visual/prototype/styles.css:22-23`（`#e3d5b6` / `#d4c4a2`）ΔL* **5.99**、对比 **1.18:1**。原文的 2.1 不可复算，且"分层弱"在两对色值上都还谈不上。【C-004 订正：不是算法之差，是成对色值之差】
4. 顶栏"存档 · 已保存"与小泽以外的两作语言不一致（这条其实该否决）。

不做：不动印章、不动台灯、不动 88px 标题、不动色板。

### 清单 B：动一处身份要素（激进）

> 【C-004 订正（E006）】正式版 `index.html` 与 `js/v2` 对 `stamp`／`已阅` **零命中**，`--stamp`（`css/v2.css:24`）只被 `:417` 的 `.v2-ending{border-left-color:var(--stamp)}` 用到；那枚"已阅"章只存在于 `visual/prototype/`。故本条在成品里没有对象，本案按"驳回"处理，不在副本内新增印章。

把**"已阅"印章**从装饰降级为**状态指示器**：印章只在"本班已结算"时出现，未结算时隐去；并把印章红从 `#9c3b2e` 提到 `#b03a2a` 以提高 25% 缩略图可读性。（`#9c3b2e` 在成品里同样 0 命中）

- 理由：印章现在是无条件装饰，读者读不出它是什么意思；给它语义可以同时减少一处"装饰性红"。
- 风险：印章是 GAME DNA 三件套之一（印章/刻度/折痕），改它可能削弱身份；且"未结算时隐去"会让主菜单右上角空一块。

## 三、已确认的约束

- 正式版一行不动；所有实验在副本 `little-zelensky-simulator-visual-copy/`（**已创建**：robocopy 排除 `.git`/`node_modules`，4600 个文件）。
- 不得为"高级感"做大改（用户原话）；不改文案主调。
- 任何一项改动都要能说明具体收益，收益必须可截图验证。

## 四、请法庭解决的分歧

1. 清单 A 的四条里，哪几条值得做、哪几条是"为改而改"？
2. 清单 B 是否允许进入试点？若允许，边界条件是什么（只副本？只截图验证？）。
3. "小幅打磨"是否等于"只修硬伤"，还是允许一次有表达意图的小改动？

## 五、失败判据

- 若改动后 25% 缩略图识别测试（3 位独立评审）比改动前**更差**，判失败、整批回退。
- 若任一改动需要动到 `index.html` 的布局骨架（`.v2-grid` 栅格），判超范围、驳回。【C-004 订正：原文写作 `.stage`，正式版无此类名，骨架容器是 `.v2-grid`】
