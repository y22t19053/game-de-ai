## 三、庭审查明的实质问题（不是程序问题）

1. **闸门只提供溯源力，不提供收敛力。** 辩方自认：847 个值可全申报，闸门只判「有没有声明」，因此「未声明值 = 0」可以被**申报率**刷绿。这是裁决从「批准」降到「pilot」的直接原因。
2. **指标族不可用作证据。** E003 用同一批指标把已验收的《小泽》V0.1 定稿判得更差（28.23 vs 23.43）；E006 证明 8 个魔法数字换 `var()` 能让字号种类 30→3 而一像素不动。故裁决明确禁用种类数/计数/像素变化作证据。
3. **执法点在当前约束下测不到真对象。** 只读 + 不改源码 ⇒ P1 注入只能打到「按 E001 复刻的对象」，不是 bistro 的真实 CSS。这条被写进裁决理由与交付口径。
4. **先零工具证伪，再投工具预算。** 唯一承重且便宜的检验是「≤7 条禁令能否承载身份」的盲配（裁决条件 C1），它不需要编译器。

## 四、执行阶段产出（真实数字）

- T01：`style.json` 73 行、7 条禁令（H1-HUE / H2-ALPHA / R1-RADIUS / T1-FONTSIZE / S1-SPACING / D1-SHADOW / X1-SLOT）+ 违宪条 U0-SINGLE-ORIGIN + 强制不规则 F1-TILT（整条可删＝对照臂）。premise 一句话：「一张奶油菜单压在木台面上，厚度一律由 `0 6px 0` 硬投影压出来」。**最先会失败的真实声明：`styles.css:43` 的 `background:#1d120c`（roles 里没有「底衬/void」这一类）**——即规则表第一稿就漏掉一整类真实值。
- T02：bistro `styles.css` 共 4748 条声明；去重 color 727 raw / 718 canonical、radius 47、font-size 57（纯 px 29）、spacing 29、shadow 144；**不可归类 1,364 / 4,748 = 28.7%**（行口径，验算后修正值）。E001 的六个数字（847/726/488带alpha/47/30/17）被逐位复现，唯 spacing 频次在 92 种口径组合下 0 匹配，如实标「未复现」。
- **验收人抓到执行者的错**：T02 报告 §7 把 26 条 `clamp()` 在 FONT 与 FONT-RESPONSIVE 重复相加，得出 70/22.3% 与 1,390/29.3%，正确应是 1,364/28.7%（行口径）。这是本轮**唯一一次第三方纠错**，也说明「执行者不得自验」不是形式。

## 五、这案子没证明什么

- 没证明「闭合文法能提升视觉一致性」——裁决明令此点在本案范围内**不可判定**。
- 没证明「≤7 条禁令能承载身份」——那正是 C1 尚未做的实验。
- 没跑 C1/C2/C3 的后续三批：本轮的交付是「裁决 + 派单 + 首批执行」，不是「试点完成」。
- 没验证七轮接线：`high` 案才会调 R1–R7，本案 `roundsChosen=0`。
- Token 未插桩：`metrics.totals.tokens = 0` 是**未测**，不是「零成本」。

## 六、如果重做这个案子

1. 争议点应在开庭时就固定为「D01 + 一个可判定的实验设计」，避免第 3 轮质询还在补既有事实。
2. 证据登记权应从提案方手里分出去（见 `docs/OPEN_ISSUES.md` I-08）：提案方选证据是结构性偏向。
3. 陪审应强制引证到 E00x（I-02），否则五票可以只写「我觉得」。
4. 先跑 C1 再开庭会更省——但那样就变成「先做后审」，制度设计的初衷相反；保留现状，把 C1 作为第一批执行任务是对的。
