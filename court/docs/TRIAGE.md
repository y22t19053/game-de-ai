# 分流规则（V0.2.0）：普通创作不走法庭

本文件是「哪些事不必开庭」的操作口径。它存在的目的不是增加一道手续，而是**防止把小事拖进法庭**——V0.1 的两桩案件（C-001 闭合文法、C-002 G2 形态）都是真的重大争议；如果每改一条文案都走一遍控辩陪审，工具就变成了负担。

## 一、三条判据（任一命中才考虑开庭）

| 判据 | 问自己 | 命中后的去向 |
|---|---|---|
| ① 不可逆 / 铺开成本高 | 这个决定一旦错了，要花多少返工才能收回？改动会外溢到多少屏、多少项目？ | 命中即至少 `major` |
| ② 有实质分歧且双方都有论据 | 是否真的存在两套都站得住的做法（不是「我还没想好」）？ | 命中且证据复杂 → `major` |
| ③ 涉及资源或责任 | 是否要押上大量人工/显存/API 预算，或事后要认定谁负责？ | 命中 → `major`；不可逆 → `high` |

**三条都不命中＝普通创作**：不需要开庭，不需要陪审，不需要证据编号。

## 二、普通创作路径（默认路径）

```
创作提案（一页，含改什么/为什么/预期收益）
  → 门下省日常审核（另开 fresh 上下文，只读提案 + 项目档案，给通过/修改/退回）
  → 尚书省执行（改副本或测试目录，不动正式版）
  → 必要检查（截图、copy_scan、核验器、测试）
  → 核销（记录：谁审的、改了什么、检查结果）
```

**硬约束**（防止普通路径被滥用成「省事的假快」）：
- 不得动正式版本、不得直接发布；只允许副本 / `visual/` / `v02_test/` 之类的工作区。
- 「小改动」不是免检理由：materials/文案类仍要跑一次检查（截图或 `copy_scan`）。
- 同一议题**第二次**被判「再改改」时，升级为 `major`（说明它不是小改动，而是方向没定）。
- 门下省日常审核必须由**非提案人**做；同一人不能既写提案又当审核。

## 三、重大争议路径（例外路径）

```
分流判定（谁判：见下）
  → 案件登记 + 证据三段式（submit → register → decide）
  → 控辩书状（claims 绑证据）
  → 争议点 + 交叉询问（≥1 轮，major 案 ≥2）
  → 5 位独立陪审（先密封初判，再读书状投终票）
  → 法官裁决（七种之一，附条件与拒绝理由）
  → 派单 → 执行 → 独立验收（checks + artifacts）
  → 先例 + 结案
```

## 四、谁做分流判断

| 情形 | 判断人 | 记录 |
|---|---|---|
| 我自己提的改动 | 提案人自判，并在提案里写明「为什么不需要开庭」 | 提案文件首段 |
| 门下省审核认为该开庭 | **门下省发起**，写明命中哪条判据 | 审核记录里的一行 `ESCALATE:` |
| 用户直接指定 | 用户 | 案件 `author` 字段记用户 |

**误判处理**：若普通路径执行到一半发现命中判据①或③，立即停手 → 开案；已做的改动作为证据入卷，不重做。

## 五、七轮否定的位置

七轮**不是默认**，仅在 `high` 案或法官认定「双方论据都缺实测」时调用；调用时每轮须写攻击目标、预期证据、停止条件（引擎 `redteam` 记录会强制这三项）。ordinary/major 案 `roundsChosen` 记 0 并写明理由（C-002 已示范）。

## 六、成本口径（两种路径分开记）

- 普通路径：记录 `审核轮次`、`人工分钟`、`检查次数`；不插桩 token（单次调用太碎）。
- 法庭路径：记录 `calls / input / output / cacheRead`（从 DSH 会话日志 `usage` 抽取，见 `docs/COST_MODEL.md` V0.2.0 节）+ 人工分钟 + 维护分钟。

## 七、本阶段实测（见 `docs/TRIAGE_REPORT.md`）

- 3 个普通任务：均未开庭，审核 1 轮，无证据编号、无陪审。
- 2 个重大争议：C-003 / C-004，均走完整程序。
- 误分流 0 次（但见 TRIAGE_REPORT 的「差点误分流」一节）。
