# 控方书状 · C-001

主张：不试点。不是"再等等"，而是这条试点在合法范围内测不到它自己声称的东西。

**一、前提已被同一份档案推翻。** 争议立在 E001 的 847/47/30 上。但 E003 用同族指标量已验收的《小泽》定稿：颜色密度 28.23 > bistro 的 23.43——同一把尺子把定稿判得更病。E006 更硬：8 个魔法数字换成 var() 就让"字号种类 30→3"而"一像素不动"。E001 自己已限口径：数的是声明不是计算值，847 里 488 是带 alpha 的 rgba、726 个出自同一文件。故 G1 只是把"数声明"换成"数未申报的声明"，仍在 E006 射程内。

**二、闸门方向是反的。** "未声明值=0"随声明集合变大而单调变松；E002 的护栏 80 行 / 200 行不限制一行里塞几个值。过闸最省力的路径是申报，不是收敛。

最可能的失败方式：试点中段 audit:close 转绿报 0，而改前改后同一屏像素一致（E006 的机制）；style.json 顶到行数上限，字号被逐条申报进去。交付的"一致性提升"实为申报率提升，换皮照旧，验收数字仍显示通过。

**三、举证责任。** 支持 G1 的只有 E002，自标"推理稿"，零执行、零工件；其独立性由提案者自评（§E.0、§E.8；J.4 自陈"计数由我判"）。而 E004 显示同一制度里"作者不得任法官"10/10 通过。这不是事实指控，是举证责任问题。

**四、合法范围内测不到核心。** E005 禁止改源码、装依赖；E001 的 726/847 集中在 src/ui/styles.css，收口必须动它。唯一合法形态是"静态编译不接 UI"，但 G1 的新意全在"构建直接失败"这个执法点——不接进真实构建，执法点不存在。且 bistro 只有 CSS 一个消费端（E001），G1 唯一新增的因果链是"一份 spec → CSS + Godot theme + 文案表"（E002），§I 又把 Godot 消费端压到 P2。试点能测的恰是最旧的一半。

**五、成本（只用提案自己的数）。** 工具 1.5 天（C6）与 4 天（§4 硬上限）自相矛盾，按 4 天算。仅 E2 一步即 2 人时 + ≈10k token，而它是六步之一。30–45 min/款只覆盖"选 premise、读 diff"，不含把 847 个声明收进集合的迁移——该迁移的对象正是 E005 禁止触碰的文件，在合法范围内不支付。显存 0，这项我让。维护 10 min/次；豁免表同占 200 行（E002），是下一个膨胀点。

**六、替代。** 不买编译器，先买纸面：每款一份 ≤7 条禁令的文档（零 token、零显存、零改动），用 E002 自己的"身份盲配 ≥70%"（自估 1 min）先测"禁令能否承载身份"——G1 唯一承重的假设，也是最便宜的检验。它先失败，编译器不必造；它通过，再用 0.5 天（E002 自估 audit:close）做只读渲染值口径测量。合计 ≤1 人时 + 0.5 天，全在 _research 与 court 内。

**要求辩护方回答：**

1. E001 的 847 里，style.json 允许申报多少个颜色值？把 847 全申报为合法、与收敛到少数，audit:close 输出有无区别？
2. E003 表上，哪一条通过标准在《小泽》V0.1 定稿上跑也不被判病？指一条并给取值。
3. 只许写 _research 与 court、不许改 bistro 源码（E005）时，试点能测到 E002 那条"spec → CSS + Godot + 文案"链的哪一环？
