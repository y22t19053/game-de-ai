## 二、论证

### 1. 提案当"设计症状"报的圆角表，数进去的是食器

`bistro-rush/src/ui/styles.css`（7608 行）有 **197** 条 `border-radius`：`999px` 33 条、`50%` 33 条、`99px` 10 条，合计 **76 条，38.6%**——它们不是设计圆角，是圆、胶囊与剪影：`:5097` 是盘（`46% 46% 34% 34% / 40% 40% 26% 26%`）、`:6657` 是碗、`:7228` 是壶（`52% 0 0 44% / 46% 0 0 34%`）。"圆角归零"落到这 76 条上不是拧一个 token，是把食器逐件重画成方的，这部分工作量提案没算。

提案 §一 的"统一 22px 圆角卡片"更不成立：`styles.css:23` 确有 `--radius: 22px`，但 `var(--radius)` 在整棵 `bistro-rush/src` 树里被引用 **0 次**——22px 是死 token；真实卡片圆角散在 `:479` 24px、`:627` 26px、`:775` 18px、`:2111` 20px。没有枢轴可拧："归零"实际是 197 条里挑 121 条手改，还得保留那 76 条几何圆。

E001 与 E002 并排，这把尺子立刻自相矛盾：浮生牌 `font_size_unique: 58`，bistro **30**；浮生牌 `radius_unique: 22`，bistro **47**。两作各赢一根轴。同一把尺子既说 bistro 更收敛又说它更烂，就不能拿它给 B 定收益（E003 已独立证成：`var()` 化能让 30 掉到 3 而渲染一像素不动）。

### 2. "重做 3 屏"装不下 B 的第二条组件语言

B 要"按钮 → 压杆式"。但按钮不是屏级组件：`.btn` 系列在 `styles.css:114–192`（`.btn` / `.primary` / `.ghost` / `.danger` / `.small` / `.big`），**调用 34 处、9 个文件**——`Title.tsx:69/74/77/80/83/86/90`、`Kitchen.tsx` 11 处，其余 7 个文件 16 处（`Settings` 4、`Tutorial` 3、`PlacementReport` 3、`Upgrades` 2、`ToyPanel` 2、`Modes:73` 1、`App.tsx:89` 1）。改全站＝超范围；只给 3 屏局部覆盖＝同一文件并存两套按钮，E001 口径的圆角/字号计数只会上涨。两条路都让"3–4 天、3 屏"这个报价失效。

### 3. B 的失败判据判不了它自己要判的东西

提案 §四 要求：改造后首页在 25% 缩略里被 3 位评审与小泽/浮生牌分开。

问题在基线：首页底色从来不是奶油。`:263` 给 `.title-screen` 暖褐底 `#2b1a10 → #130c08`；`:3018` 又定义一次，换成 `#1b1030 → #080510` 的霓虹紫底加粉青光（`:3020–3022`）；同权重、后出现者胜，所以**今天**玩家看到的是暗底亮字。而 E005 §4 说小泽在 25% 下读作"被灯照亮的一块纸 + 暗的桌面"，暗底亮字与其必然可分——**判据今天就已经通过**。没换骨也通过的判据，抓不到没换骨。

改造后更糟：全屏冷白 `#f4f1ea` 把整页亮度反转一次，25% 下更醒目、通过更容易。而 B 主打的 1.5px 硬边、2px 圆角、打孔边，在 390×844 缩到 25%（97×211）后是 0.375 / 0.5 / 0.5 像素，物理上不可见。**判据测的是亮度，B 卖的是边距。** 无论 B 成败它都亮绿灯，因此它不是判据，是仪式。

E005 还给出方向风险：小泽第三条律是"圆角 ≤2px"、第一条是"纸必须像纸"，B 的"圆角 0/2px + 打孔纸"是同一句式；而 E005 §5 写 bistro 的识别点是"暖橙圆角、无纸"——B 抹掉的恰是这两条，不是分家，是搬进对方院子。
