# 为什么是「法庭」，而不是一张 checklist

## checklist 是怎么烂掉的

我们真的先用过 checklist：「美术方向确认 / 素材进清单 / 预览截图 / 移动端跑过 / 文案审过」。三个月后它的实际状态是：

- 每一项都有人勾，但没人能说清勾的依据是什么；
- 攒到最后一天批量勾，因为「反正都要勾完才能发」；
- 有人勾了「预览截图」，附的图是两周前的；
- 唯一能拦人的是签核人自己，而签核人就是写代码的那个人。

checklist 的病不在不够长，在**它是自证的**：自己说自己过了，就过了。

## 法庭给出的三样东西

| | checklist | 法庭 |
|---|---|---|
| 谁来判断 | 执行者自己 | 不参与执行的人，且方案作者不得任法官 |
| 依据 | 一个勾 | 一条已入卷证据，挂在某个具体论点上 |
| 理由 | 无 | ≥20 字，可被反驳、可被援引、可被推翻 |
| 留痕 | 无 | 追加式哈希链，改一个字重算即红 |
| 失败方式 | 忘了勾 | 拒绝执行，带拒绝码 |

第二行是核心。**「说完成」要有成本**：说一次「做好了」，就要交出一张能打开的证据；交不出，命令直接报错，不是提醒你一下。

## 三条设计取舍

**1. 证据分型优先于证据数量。** 53 条证据听起来多，价值不在多，在每条都标了来源（`raw` / `run` / `external` / `expert` / `inference` / `assumption` / `judgment`）。模型自己推理出来的东西只能是 `inference`，而 `inference` 一旦被标成「已独立验证」，引擎直接抛 `EVIDENCE_LAUNDERING`。这就是 C-001 认定的边界：**闸门保来源力，不保收敛力**——十条同一来源的证据不会因为条数变成更强的结论。

**2. 程序不可跳。** 未裁决不得派执行任务（`NO_RULING`）；有未销任务不得结案。这两条让人没法「先干起来再说」，也没法「活没干完先宣布收工」。代价是慢，收益是事后每一份「已完成」都能倒查回是谁在什么证据上签的字。

**3. 审计只记录、不追缴。** 逾期任务记进审计（现在是 9 条），初判迟到记进审计（现在是 55 条），但系统不阻断、不自动催。**一个会自动变绿的审计器等于没有审计器。** 红灯留在那里，是为了让人每次跑 `audit verify` 都看见自己欠了什么。

## 它不是

- 不是质量评分器。它不判断游戏好不好，只判断「你声称的事有没有证据」。
- 不是自动评审。AI 评审和 AI 作者是同一个底模时，那只是自己夸自己。
- 不是替代人拍板。视觉方向确认那一步**必须停等真人**，法庭不管美学。

## 什么时候不该用它

- 三天做完的 jam 作品：走一次完整程序的成本高于作品本身。用 `docs/GATES.md` 里三行的投稿闸门就够。
- 纯探索的美术原型：还没有「主张」的时候，证据无从谈起，先把方向聊出来（`skills/game-de-ai/` 的 A–C 步）。
- 身边没有第二个人的项目：可以跑，但要知道独立性只剩「独立上下文」一层，见 README 的「限制」。
