# 三类证据，不得混用

做游戏时，你手上永远有三种完全不同的「证据」，它们证明的东西不重叠。混用一次，后面所有判断都不可信。

| 类 | 是什么 | 它能证明 | 它**不能**证明 |
|---|---|---|---|
| **机械证据** | 测试、断言、日志、截图产物、哈希、构建退出码 | 某个行为在某个输入下确实发生了 | 好玩、好看、目标玩家能懂 |
| **真人证据** | 真人试玩记录、观感描述、盲测结果、口述踩坑 | 有人真的这样体验到了 | 代码路径正确、边界情况没炸 |
| **发行证据** | 商店页、投稿状态、播放量、评论、审核结果 | 它确实被发出去了、有人看见了 | 它确实能跑、它确实值得被看见 |

三条最常见的混用，每条都配一个真事：

**1. 用机械证据顶真人证据 ——「27 个测试全绿，这游戏没问题。」**
测试全绿只证明测试写到了那里。我们自己的观感缺陷（地图太小、流程太短、不知道收集物品干什么、场记板之外几乎没有声音）一条都不会让测试变红。测试是防回归的，不是体验的代理。

**2. 用发行证据顶机械证据 ——「已经上架了，说明能跑。」**
上架证明的是文件能下载。发行包少一个 autoload 脚本会在启动时直接崩，而商店页照样在。能跑要在真机器上跑一次，且看运行时日志的 error 行，不看退出码。

**3. 用真人证据顶机械证据 ——「玩家都说没问题。」**
玩家在正常路径上看不到边界情况。三个人都说流畅，不代表 200 人在低端机上的加载不会卡死。

## 推论只能是推论

模型自己的分析、审美判断、"我觉得这里更好"——这类东西单独一类：`inference`。它可以进卷，但不能被标成「已独立验证」。`court` 里这条是硬错误：

```
EVIDENCE_LAUNDERING  模型推论不得标记为已独立验证
```

理由很实际：如果推论证言可以升级成事实，那整套证据体系就退化成「谁话多信谁」。

## 和 court 的证据类型对应

`court/src/court.mjs` 里的 `EVIDENCE_KINDS`：

| kind | 含义 | 对应上面哪类 |
|---|---|---|
| `raw` | 原始文件 / 日志 / 截图，未经加工 | 机械 |
| `run` | 一次具体运行的输出（测试、构建、实机） | 机械 |
| `external` | 外部系统的事实（商店页状态、投稿回执、作品页 URL） | 发行 |
| `expert` | 由人给出的专业意见（真人试玩、外部评审） | 真人 |
| `inference` | 模型或作者的推论 | ——（推论层） |
| `assumption` | 明确标记的假设（"我们假设玩家看得懂图标"） | ——（假设层） |
| `judgment` | 已经作出的判断（裁决、定论） | ——（结论层） |

前四类可入卷作证据；后三类是**必须被标明身份**的东西，混进前四类就是伪造。

## 每次开口前先标类型

简单到能立刻用的规矩：说一句关于作品的判断，前面加一个标签。

- `[机械]` 27 个测试通过，构建退出码 0 —— 依据：`court/test/*` 输出
- `[真人]` 三个新玩家第一次都卡在第二关门口 —— 依据：试玩记录
- `[发行]` itch 页面已通过审核，可下载 —— 依据：商店页 URL

标不出来源的判断，就不该说成事实。这条规矩比任何工具都便宜，也比任何工具都有效。
